## 步骤与观察
1. **问题 1 根因**：saveChatSection/saveNetwork 的动态 `import("../api.js")` 少一级（应 `../../api.js`）——模块解析失败被 async handler 静默吞，点击完全无效且无提示；WS 直调 host 端同链路完全正常（锅纯在 UI 层）。修=静态 import + settingsCache 即时回填。IAB 实测"剩余/pwsh"点击实时切换。
2. **问题 2 根因（本轮最重）**：read/write/edit/glob/grep/pwsh/apply_patch 七个 builtin 工具的 ToolDef **没有 parameters 字段**——toChatTools 兜底 `properties:{}` 空 schema 发给模型，模型无从传参全部空调用失败（模型思考原话"the schemas listed have empty properties"）。此前从未暴露=走查全用 echo provider（不消费 schema）。修=七个 schema 补齐（形状对齐 execute 校验）；node 直跑编译产物断言 ALL SCHEMAS OK。
3. **黄色横幅误报**：恢复视图检测到未闭合轮 → "检测到中断的轮"黄条；但轮在跑（busy）时这是正常状态。修=busy 时跳过横幅（补广播保留）。
4. **调研（两份 Explore 报告）**：
   - zcode：工具失败=状态词+虚线下划线+tooltip（无红圈不染红）；运行态=动作词扫光非转圈；思考默认收起+折叠态末行摘要渐隐；toast 只留"用户动作结果+被阻解释"两类，agent 自主过程全部流内呈现。
   - pi-desktop：**没有字面打字机**（决策 D152 拒绝 rAF 打字循环）——过程感=帧级合并直出+增量 markdown 分块缓存（已定稿块零重解析）+常驻尾部状态行（三点跳动+相位文案+计时）+motion token。
5. **问题 3 落地**：①typeStream 废"纯 textContent 打字→终态 innerHTML 整段替换"两段式（生硬根源）——splitMarkdownBlocks（空行分块+围栏感知）+renderMarkdownBlocks（已定稿块以源文本为 key 跳过赋值、尾块每帧重渲染、终态同路径零跳变）；②常驻状态行（turn/start 挂载三点+秒计时、首 token 不隐藏、审批卡让位、turn/end/resetStreamView 卸载；appendStreamNode 插到状态行之前）；③工具失败态中性化（setToolStatus 去图标、has-error-detail 虚线下划线+title、error summary 去整行染红）；④思考块缺省改 concise（zcode 语义）+折叠态末行摘要（think-preview 渐隐 mask，展开隐藏）。
6. **问题 4 落地**：删四处高频 toast——新建任务（直接进入即反馈）、config_refreshed 热切换（pill 即反馈）、代理保存/关闭行为保存（分节说明文字已承载生效时机）。设置页动作结果类 toast 全保留。
