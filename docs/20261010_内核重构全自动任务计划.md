## §1 执行规则（任务模式专用）

### 1.1 每个任务的固定循环

```
1. 读任务卡（目标/动作/文件/验收/依赖/依据）
2. 检查依赖项是否已 [x]（未完成则先做依赖）
3. 执行动作（改代码；纯搬迁用 git mv 保历史）
4. 跑验收命令（见 1.4）——必须全过
5. 打勾：把 `- [ ]` 改成 `- [x]`，并在行尾追加 `｜完成：YYYY-MM-DD，commit <sha7>`
6. git add + commit（中文 message，含任务 ID）
7. 更新 §2 状态总表对应阶段进度
8. 进入下一项
```

### 1.2 打勾格式（严格）

```markdown
- [x] **T3-6 W5 工具契约元数据** ｜完成：2026-10-11，commit a1b2c3d
```

未完成的保持 `- [ ]`。**只有验收全过才允许打勾**；验收不过 → 修到过，或触发 §1.3 停止条件。

### 1.3 停止条件（仅这三种，其余一律自行决策继续）

1. **同一验收连续两次修不好** → 记录失败详情，停止并报告（附：任务 ID、失败命令、报错、已试方案）。
2. **触达用户红线** → 需要 `rm -rf`/`sudo`/`git push tag`/改 `oss/`/改工作区外文件/提交敏感信息 → 停止并报告。
3. **发现计划与事实冲突**（如文件不存在、依赖方向与描述不符）→ 记录冲突，按"以事实为准 + 最小偏离"处理并在任务卡下方记档，不擅自扩大范围。

> **注意**：批 5 原方案写"停一轮给用户看 diff"，但用户已选择**全自动**——改为**硬闸**：批 5 的阶段闸（T5-6）必须真 host 冒烟 + 端到端全过，否则按停止条件 1 处理。

### 1.4 验收命令（每任务至少跑前三条）

```bash
npx vitest run                 # 全量（基线 2230 绿，重构中不得下降）
npx tsc --noEmit               # 类型干净
node tools/architecture-check.mjs   # 无新增 error；core 域零违规
```
**运行面任务追加**（批 5/6/7、阶段 9）：
```bash
node scratch/smoke-host.mjs    # 真 host 冒烟（WS 全 op 响应）
# 真模型轮：走真实 provider 跑一轮工具调用（成功率 + 事件流完整）
# 便携重打：npm run build:single && corepack pnpm run tauri:build → 三哈希核对
```

### 1.5 提交纪律

- **每任务一 commit**（中文 message：`<type>(kernel): T<id> <一句话>`）。
- 阶段末（阶段闸）额外一次 `docs(kernel): 阶段 N 收官` commit（含状态表更新 + notes）。
- **不推 tag**（`research/v1` 指向旧历史）；`git push origin main` 允许在**阶段末**执行（用户已授权，仅推 main）。
- 会话三件套：每阶段末更新 `docs/handoff/` + `notes/`（按 AGENTS.md）。
