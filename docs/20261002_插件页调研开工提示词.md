## 3. 摸底锚点（本会话已查，下会话直接深读）

### 3.1 我方现状（基线）
- 清单：`src/kernel/plugin-manifest.ts`（242 行）——字段闭集 {name, trust, capabilities, hooks}、安装期全量校验 fail-closed（pi validation.rs 同款）、贡献 hooks 注册进 HookRegistry（trust 分轨）；
- 装载：`src/kernel/plugin-loader.ts`（159 行）——inprocess / ws 两种形态、装配期装载、单插件失败 never-fail；
- 管理：`src/host/plugins-gateway.ts`（178 行）——plugins-list op（安装期校验诊断）；
- 已有插件化面：**主题即插件**（T-P3-141：manifest.theme 字段 + plugin-theme-css op + 入口按需）；UI `agents.js` 插件分节（安装/清单/启停）。
- 差距方向：无面板/命令贡献、无模板创建、无市场、无打包发布链、无 SDK。

### 3.2 pi-desktop（重点仓 1）
- `packages/plugin-sdk/src/`：bus-topics.ts（插件↔宿主总线主题）、fs-policy.ts（文件面策略）、index.ts（SDK 契约）；
- `packages/plugin-devkit/src/`：**templates.ts（四模板：panel-basic / agent-tool / skill-pack / full-demo——与用户截图的"面板/智能体工具/技能包/全部能力"一一对应）**、cli.ts（devkit CLI）、pack.ts / publish.ts / check.ts（打包/发布/校验链）、walk.ts；
- 扩展页 UI：已安装/市场两 tab + 渠道下拉 + 分类 tag + 安装次数（用户截图）；
- 宿主侧：插件贡献命令/工具/hook 的注册与生命周期（agent-ipc/plugin-services 深读）。

### 3.3 deepseek-harness（重点仓 2，"dsh"）
- `packages/extensions/`：**cordis-client-runner / cordis-host-runner / tool-cordis / ui-cordis**——cordis 系插件运行时（koishi 架构：ctx 事件总线 + 插件声明式服务）；
- `scripts/gen-plugin-packages.ts`——插件包生成器（模板化创建的 dsh 形态）；
- 深读点：插件包 manifest/加载器/权限面/ui-cordis 的 UI 贡献方式。

### 3.4 zcode（模板创建 + git 市场先例）
- plugin-creator skill（用户点名"调用工具来创建"——skill 用工具按清单生成插件骨架）；
- 官方市场缓存：`~/.zcode/cli/plugins/cache/zcode-plugins-official/<plugin>/<version>/`（git 仓库即市场的缓存形态）；marketplace manifest 结构（plugin-marketplaces.ts）；
- 插件贡献组件：commands/hooks/MCP servers/skills（T-P3-146 zcode 调研已证）。

### 3.5 其余（批 2 扫）
- opencode：plugin 目录 + 插件钩子（experimental.* 面）；codex：plugins.rs（本地/git/npm/remote 四源）；cc-switch（若无插件面则一句话带过）。
