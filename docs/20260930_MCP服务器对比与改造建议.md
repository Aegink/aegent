## 0. 结论一句话

用户三点诉求（外部扫描导入 / 双形式新建 / 单 server 真实测试）在参考仓全部有成熟先例，
且**第三点我方内核已具备**（`probeServer` 真握手探针已在位，只是没接到列表行上）；
改造规模 = 1 个新 host op（扫描导入）+ 1 个内核小扩（env/timeoutMs 透传）+ MCP 分节 UI 重做，
零新增依赖（Codex TOML 用手写最小解析器——pi-desktop 同款先例）。

## 2. 我方现状与差距

现状（MCP 分节在 `ui/views/settings/agents.js:34-66` 向导 + `:250-303` 列表；
后端 `src/mcp/client.ts`（JSON-RPC over stdio，initialize/tools/list/call，10s 超时）+
`src/mcp/registry-bridge.ts`（`connectAndRegister` 命名空间化注册 / `probeServer` 探针）；
host `settings-gateway.ts:292-297` `mcpCheck` op（8s 超时）；装配消费 `agent-process.ts:441-448`
顺序连接、单 server 失败 never-fail 跳过）。

| 能力 | 我方现状 | 差距 |
| --- | --- | --- |
| 列表 | 图标座+状态点（绿/红/灰）+ 启停开关 + 删除 + 点标题进向导 | 缺工具数徽章、缺"未测"与"成功"区分、缺导入入口 |
| 新建 | 两步向导（stdio 表单 → 测连接 → 保存） | 缺 env 字段、缺超时字段、缺 JSON 粘贴模式 |
| 真实测试 | 向导内"测连接"（真握手，结果：协议版本+工具数） | 缺**列表行级**测试按钮；结果只在向导里一次性展示 |
| schema | `{name, command, args?, enabled?}` | 缺 `env`（很多 server 必须 API key 注入）、缺 `timeoutMs`（慢启动 server） |
| 导入 | 无 | 全缺 |
| transport | 仅 stdio（内核 LIMITATIONS 记档） | 表单诚实保持 stdio 单项，不放假的 HTTP/SSE 下拉 |

### 3.2 opencode

- 配置 schema（`packages/core/src/v1/config/mcp.ts:6-60`）：local `{type:"local",
  command:[数组], cwd, environment, enabled, timeout}` / remote `{type:"remote", url,
  headers, oauth, enabled, timeout}`；无 type 的条目启动忽略并 logError。
- 客户端（`packages/opencode/src/mcp/index.ts`）：connect 超时包裹、失败仅标 `failed`
  不拖累其他 server（`:383-387`）；**无自动重连**；断开即删工具并广播 ToolsChanged。
- **`mcp debug <name>`**（`cli/cmd/mcp.ts:730-835`）：裸 initialize POST 单探针——
  轻量判定"活着/需要认证/挂了"。
- 值得抄：enable/disable 语义（disabled 启动跳过；connect 强制重建）、unbounded 并行启动
  + 每 server 独立 catch、宽松 schema 降级重试。

### 3.3 codex（Rust）

- config.toml `mcp_servers`（`codex-rs/config/src/mcp_types.rs:217-403`）：**无 type 键**
  （command→stdio / url→http 互斥推断）；`{command, args, env, cwd, startup_timeout_sec,
  tool_timeout_sec, enabled, required}`；`deny_unknown_fields` 严格校验。
- CLI `codex mcp add/list/remove/login`（`cli/src/mcp_cmd.rs:64-72`）：add 是 flags 式
  **不接受 JSON 粘贴**；list **不做握手探测**（注释明说 "it has never initialized"）。
- 握手：initialize 固定协议版本、spawn+connect 整段 `startup_timeout`（默认 30s）包裹
  （`codex-mcp/src/rmcp_client.rs:339-377`）；每 server 一个并行任务 + 状态事件流。
- Windows：`which` crate 按 PATHEXT 把 `npx` 解析成 `.cmd` 全路径（`program_resolver.rs:40-65`）；
  Job Object 挂起-再分配、失败降级重新 spawn（`stdio_server_launcher.rs:293-357`）。

## 4. 改造方案（A~F）

> 顺序即依赖序：E（schema/内核）是 A/B/C 的前置；D 独立但落在同一 UI 重做里。
> 全部零新增 npm 依赖。

### E. schema 与内核配套（前置）

- `McpServerEntry`（`src/session/settings.ts:178-188`）+= `env?: Record<string,string>`
  （string:string 校验）、`timeoutMs?: number`（正数校验）。
- `McpServerConfig`（`registry-bridge.ts:16-21`）+= `env?`、`timeoutMs?`；
  `createMcpStdioTransport`（`client.ts:188`）spawn 增加 `env: {...process.env 择要, ...entry.env}`
  （**不整包继承**——MCP server 只需 PATH/HOME 等运行面，缩小凭据泄漏面，参考 cc-switch
  写前剥离思想）；`probeServer`/`connectAndRegister` 透传 env 与 per-request 超时。
- 装配点 `agent-process.ts:442-448` 无需改（cfg 直接来自 parse 后的 entry 映射）。
- 验收：vitest（parseSettingsShape env/timeoutMs 用例 + transport env 合并 + probe 透传）。

### A. 外部配置扫描导入（用户点 1）

- 新 host op `mcp-import-scan`（新文件 `src/host/mcp-import-op.ts`——行数纪律拆分位，
  settings-gateway 398 行近 400 上限）：
  - 扫描源表（每源 `{label, paths[], format}`；homeDir 从网关注入（`:230` 已有）——测试可注临时目录）：
    - Claude Code：`~/.claude.json`（mcpServers）+ `~/.claude/settings.json`
    - Claude Desktop：`%APPDATA%\Claude\claude_desktop_config.json`（qwen/pi-desktop 先例）
    - Codex CLI：`~/.codex/config.toml`——**手写最小 TOML 解析器**只解
      `[mcp_servers.<name>]` 的 command/args/env（字符串数组/内联表三种形状），
      pi-desktop 同款零依赖方案；容错 `[mcp.servers.*]`（cc-switch 先例）
    - Cursor：`~/.cursor/mcp.json`（mcpServers）
    - OpenCode：`~/.config/opencode/opencode.json`（mcp 键，local/remote 归一化——
      zcode `normalizeOpenCodeMcpConfig` 同构；command 数组拆 command+args）
    - Qwen Code：`~/.qwen/settings.json`；Trae：`~/.trae/settings.json`；
      通用：`~/.agents/mcp.json`（三源同形状 mcpServers，共用解析）
    - 工作区：`<workspaceRoot>/.mcp.json`（Claude 约定；workspaceRoot 网关已有，`:225`）
  - 产出 `{sources: [{label, path, exists, count?, error?}], candidates: [{name, config:
    {command, args?, env?}, sourceLabel, sourcePath}]}`——每源一行报告不静默（pi-desktop 形态）；
    候选按字段内容判形状、剥 timeout 类外部字段（zcode `stripExternalMcpTimeoutFields` 同构）。
- UI（agents.js MCP 分节头部加「导入」按钮 + 模态）：
  打开即扫 + 手动刷新；来源分组行（勾选框 + 名称 + 命令 mono 副文本 + 来源徽章）；
  全选 + 已选计数；导入 = 过滤同名已存在（skip 计入结果）→ push 进 settingsCache.mcp →
  markDirty（**导入只进缓存待保存，与现有"保存"闸一致**——不搞第二落盘通道）；
  结果 toast（导入 N / 跳过 M[重名] / 失败 K）。
- 验收：走查档预置假 `.codex/config.toml` + `.cursor/mcp.json` + `.claude.json` →
  扫出候选 → 勾选导入 → 列表出现 → 保存落档 → 重开仍在；重名 skip。

### B. 双形式新建（用户点 2）

- 向导重做（保持内嵌卡或下沉模态——实施时按现有 Dialog 形态选）：
  右上「表单 | JSON」分段切换（zcode 分段 tab 形态）。
- 表单模式：名称 / 启动命令 / 参数（空格分隔）/ 环境变量（折叠区，JSON 文本域
  `{"KEY":"VALUE"}`——zcode 同款；解析失败红字提示）/ 超时 MS（可选，placeholder 10000）。
  保存校验：名称非空不含 `__`、命令非空（cc-switch 同规则）。
- JSON 模式三形状（zcode `jsonDraftToForm` 同构）：`{"name":{...}}` / `{"mcpServers":
  {"name":{...}}}`（单条取第一条，多条报"一次只添加一个"）/ 裸 config（带 command）；
  解析失败红字在文本域下，不炸；两模式来回转换（表单→JSON 草稿、JSON→表单回填，
  转换失败弹回原模式）。
- 测试闸保留：JSON 模式同样先「测连接」再允许保存（现状 fail-closed 闸不放松）。
- 验收：三种粘贴形状各录一遍 + 坏 JSON + 多 server 包装对象报错；保存后列表/落档正确。

### C. 行级真实测试（用户点 3）

- 列表每行加「测试」按钮 → 复用既有 `mcp-check` op（`settings-gateway.ts:292`，
  probeServer 真握手）→ 行内状态刷新：成功 = 状态点绿 + 工具数徽章（最近一次测试结果，
  内存缓存——不落 settings 防污染单一事实源）+ toast「N 个工具」；失败 = 状态点红 +
  失败消息（行内 desc 位置红字，zcode 失败文案+详情形态的轻量版）。
- 状态点语义升级为四态（zcode 同构）：绿=已启用且最近测过成功 / 灰=已停用 /
  红=最近测失败 / 无点=启用但未测过（title 文案区分）。
- 成功结果展示前 24 个工具名（pi-desktop `MCP_TEST_TOOL_NAME_LIMIT` 形态）——
  放在测试按钮的 toast/展开行里。
- 验收：对 mock server（scratch 已有 mock 面）行内测试成功态；对坏命令测试失败态；
  测试中按钮防重入。

### D. 列表信息面丰富

- 行加：工具数徽章（最近一次测试缓存）、env 存在性 chip（"含 env"——不显值防凭据，
  cc-switch 搜索排除 env 思想）、来源徽章（"导入自 Codex"——A 导入时记 sourceLabel 到
  内存，不落档）。
- 空状态改双按钮引导：新建 / 导入（zcode 空状态双 CTA 形态）。
- 验收：走查截图核对形态与既有行规范一致（266×34 控件纪律）。

### F. 明确不做（记档）

- **HTTP/SSE transport**：内核仅 stdio（`client.ts` LIMITATIONS 已记）——表单不加 url
  字段、类型下拉保持 stdio 单项（诚实不放假选项）；HTTP transport 是独立内核扩展位。
- **协议版本下拉**（zcode 的 自动/legacy/v2）：我方内核固定 `2024-11-05` 协商
  （`client.ts:23`），做下拉=假功能，不取。
