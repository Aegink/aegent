## 一、参考项目的"权限"设置面长什么样

### 1. 权限模式（Permission Mode）——**所有家都有，我方完全没有**

这是参考项目权限设置的第一项，也是用户日常用的开关。各家档位光谱：

| 项目 | 档位（从严到松） | 全局/会话双层 |
| --- | --- | --- |
| claude-official | default（manual）/ acceptEdits（编辑自动批）/ plan（只读规划）/ bypassPermissions / auto（分类器判） | ✓（defaultMode + 会话 `--permission-mode`） |
| agentscope | DEFAULT / ACCEPT_EDITS / **EXPLORE（只读）** / BYPASS / **DONT_ASK（ask→deny）** | ✓（channel/session/schedule 各级字段） |
| qwen-code | plan / default / auto-edit / auto / **yolo** | ✓（settingsSchema + 会话斜杠命令） |
| kimi-code | manual（Always Ask）/ auto（Ask When Needed）/ yolo（Never Ask） | ✓（config.toml + 运行态切换） |
| grok-build | default / ask / auto / always-approve | ✓（ui.permission_mode + remember_mode 跨会话记住） |
| pi-desktop | ask / accept-edits / auto | ✓（全局默认 + Composer 每会话菜单 inherit） |
| opencode | 无模式，但**分工具** permission（见 §2） | agent 级可覆盖 |
| hermes | approvals.mode：manual / smart / off | + unattended/cron/single_query 三种无人值守面单独定 deny/approve |

共性结论：**档位光谱 = 全问 ←→ 编辑自动批 ←→ 只读 ←→ 全自动（仍拦 deny）←→ 无人值守安全（ask 转 deny）**。
agentscope 原文还专门划了界限："无人值守且仍需安全时，用 DONT_ASK 而不是 BYPASS"。

### 2. 会话内审批交互——"记住选择"（三家做了，我方审批卡只有同意/拒绝）

| 项目 | 审批选项 | 记住的方式 |
| --- | --- | --- |
| opencode | Allow once / **Allow always** / Reject | always 写会话 approved 集合，同类后续自动放行（permission/index.ts:145） |
| pi-desktop | allow-once / **allow-session** / deny | 会话级（PermissionCard.tsx:34） |
| claude | Yes / **Yes, and don't ask again** / No | 写回项目 settings.local.json（跨会话） |
| hermes | 批准 / 拒绝 / **command_allowlist 永久放行** | 写 config（tools/approval.py:397） |
| 我方 | 同意 / 拒绝（两键） | **无**——每次都要重新批 |

### 3. 规则作用域分层

kimi 四层、qwen `system|user|workspace|session`、claude `managed→user→project→local`。
**我方内核已实现四档**（C22：project / user / session-runtime / turn-override——
`rule-scope.ts`），但**审批 UX 未接**：审批时无法选"本会话内别再问"，规则文件只有 user 层一个入口。

### 4. 分工具默认策略

opencode：`permission: { bash: {…}, edit: {…}, webfetch: {…}, "*": … }` 每工具独立 ask/allow/deny。
我方：规则文本可等价表达（`Bash(*) -> ask` 等），但无结构化快捷区。

### 5. 其他差异化设计（供参考）

- codex：审批策略与**沙箱模式成对联动**（approval=never 时沙箱外命令自动拒绝）；permissions **profile + extends 继承**（`:workspace` 内置档）。
- qwen：**AUTO 分类器**（LLM 判官自动判 allow/ask，两级超时可配）——07-permission.md §4 有完整调研。
- grok：`features.remember_mode` 跨会话记住上次模式；`ui.default_selected_permission` 审批行预选。
- claude：headless `--permission-prompts none`（无人值守自动拒）；MDM 托管层。

## 二、我方现状

**内核（`src/policy`，45 文件——底子很好）**：决策规则（`Tool(args)` 文本、首匹配胜、通配/参数匹配、invalid 标记）、危险命令清单、保护名/保护路径、IMDS/SSRF 黑名单、审批挂起/超时/审计字段、判定守卫、策略自检 linter、**作用域四档已实现**（rule-scope.ts）、"批准记多久"能力面（C47）已在。

**UI（太薄——您感觉"太少"的根源）**：权限档页只有审批超时 + 规则管理（刚做的）。缺的不是底层能力，而是：
1. **没有权限模式**——用户想"别每次都问"时，只能手写 allow 规则；
2. **审批卡没有"记住选择"**——内核的 session-runtime/turn-override 作用域在，但审批卡只给同意/拒绝两键，能力面闲置。

## 三、改造建议（请拍板，我按选择实施）

| # | 改造项 | 内容 | 参考谁 | 内核工作量 | 优先级建议 |
| --- | --- | --- | --- | --- | --- |
| **A** | **权限模式**（最大缺口） | 五档：每次询问（默认）/ 自动批编辑（工作区内文件写自动放行）/ 只读（拒绝一切修改）/ 全自动（仍拦 deny 规则与内置保护）/ 无人值守（ask→deny）。全局默认（settings.permission.mode）+ 会话内切换（Composer 权限菜单 / 斜杠命令） | agentscope 五档 + pi-desktop 全局/会话双层 | 中——gate 层加模式映射 + 装配传参 | **P0（推荐）** |
| **B** | **审批卡"记住选择"** | 审批卡三选：允许一次 / **本会话内允许** / 拒绝——选"本会话内允许"后同类调用不再打断 | opencode + pi-desktop | 小——C22/C47 能力面已在，只接审批 UX | **P1（推荐）** |
| **C** | 规则作用域显性化 | 规则清单显示来源层（user/项目）；项目层规则文件入口 | kimi/qwen 分层 | 小-中（查 project 层文件位是否已接） | P1 |
| **D** | 分工具默认策略快捷区 | Bash/Edit/Write/WebFetch/MCP 各一个默认动作下拉 → 落成规则文件条目 | opencode | 小（写规则文件的等价糖） | P2 |
| **E** | 审批历史 | 最近审批记录（谁批的/何时/哪条规则命中）——审计字段已落库 | hermes/claude | 小-中（查询面） | P2 |
| **F** | 不建议做 | 服务端签名策略（07 文档已列非目标）、MDM 企业锁定、codex 式沙箱深联动（沙箱档独立页已有） | — | — | — |

**我的推荐组合：A + B 一起做**（权限模式解决"和权限这个词不一样"——它才是权限设置的主体；审批记住选择解决"每次都要重新批"——两者合起来就是参考项目权限面的 80%，且 B 几乎纯 UX 接线）。C 顺带，D/E 看您意愿。

**请裁决**：全做（A+B+C+D+E）/ 推荐组合（A+B）/ 自选编号。

## 四、实施记录（2026-09-30 用户裁决"全做（A~E）"——commit 94abed8）
