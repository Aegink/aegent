## 0 · 一句话结论

**aegent 内核现在单独完整可用**（core 纯内核 + runtime 装配 + ext-builtin 能力面 +
models/session/policy 等域支撑，四连绿 + 冒烟 + 便携真机冒烟全过），**架构哲学与 pi
同宗**（最小循环内核 + 策略全钩子化 + 应用能力外置），但两仓走向了不同的极：
pi 把"极简"做到极致（内核 2519 行、零权限子系统、扩展即进程内 TS 模块），aegent
把"产品化治理"做到极致（权限四层链 + 审批竞速 + 规则写回 + 插件 manifest/能力分片 +
进程隔离 + SQLite 事件源）。**互有明显取欠：aegent 有 pi 没有的治理与编排全栈；
pi 有 aegent 没有的 41 家 provider 目录、类型化 schema 体系与实验性 durable 事务化路线。**

## 3 · 逐面对照

### 3.1 agent 循环

- **pi**（`packages/agent/src/agent-loop.ts` 949 行）：双层 while（外层 follow-up/
  内层 tool-call 链）；队列 `all | one-at-a-time` 双语义 + steer/followUp 双队列；
  四个策略钩子（prepareNextTurn/prepareRequest/finishTurn/before·afterToolCall）；
  **"length 截断即整批 tool call 判失败"** 的配平纪律；`terminate` 需整批一致才早停；
  并行工具"顺序预检、并发执行"，result 消息按源序补发；工具负载差量
  （toolsAdded/toolsRemoved 写进系统消息——模型可见的工具集变更靠转录表达）。
- **aegent**（`src/core/primitives/loop/`，loop.ts 1,582 行 + guards/watchdog/
  stream-recovery/queue 等 9 分件）：turn→step→message 三级；PromptQueue 三节奏
  （all/one-at-a-time/mode 可配）+ 优先级 now/next/later + 有限队列上限 + 顿号
  老龄化提升；watchdog 武装/迟到闸门不回填/流恢复；**33 种事件闭集词汇表**
  （C14/C16：新增类型必须同步更新闭集 + JSON 安全断言 + 投影校验）；
  mutationBudget/guards 变异护栏；thinking 七档。
- **判定**：循环语义两者同构（pi 的队列语义是 T9-2 steer 残留续跑的对照原型）。
  aegent 的护栏（watchdog/流恢复/变异预算/词汇闭集）**强于 pi**；pi 的"截断整批
  拒绝"配平纪律与工具负载差量声明是两个**我方可借鉴的细节**（P3 级）。

### 3.2 会话存储与投影

- **pi**（coding-agent/session-manager.ts 2,013 行）：**JSONL 树**——entry 带
  id/parentId，leaf 指针定位，分支=移 leaf 再追加（不改历史）；entry 词汇 11 种
  （message/compaction/branch_summary/custom/context_edit/label/…）；fork=拷贝
  全部 entry 到新文件 + parentSession 指针；版本迁移 v1→v3；压缩结果也是一种
  entry 持久化（compaction entry 折叠为上下文边界）。
- **aegent**（`src/session/` 38 文件/8,478 行）：**SQLite 事件流**——33 事件闭集
  append-only + seq 主键 + write-behind 串行 flush（G1：seq 必须前进）+ restore
  三级降级（strict/lenient/discard，G2）+ E16 投影校验器（fold 重建任何投影）+
  commit 原子批（事件+标题+血统+插件文档同事务）+ ignorable 信封（前向兼容：
  闭集外事件标注 ignorable 可跳、无标注 fail-closed 拒读——本轮修复后 SQLite 与
  内存后端槽位纪律统一）+ session/fork/checkpoint/archive 事件级分支回退。
- **判定**：pi 的 JSONL 树把"分支导航"做成一等数据（树遍历 + label 书签 +
  context_edit 历史覆写），**交互式分支体验强于我方**；我方的 SQLite 路线在
  **崩溃语义（单事务原子界）、双进程写序、信封前向兼容、投影可重建性**上
  **强于 pi**（pi 的 custom entry 也有类似前向兼容位，但无 fail-closed 语义）。
  各自匹配产品形态：pi 单机 TUI，我方多端多进程。

### 3.3 工具面

- **pi**：内置 **8 工具**（read/bash/powershell/edit/write/grep/find/ls）；每个
  工具配 `XxxOperations` 接口（后端整体可替换——远程 env/沙箱）；文件变更串行
  队列；统一截断与渲染器。schema 用 typebox。
- **aegent**：**42 个可注册工具**（16 常驻 + 26 条件注册：trace×3/task 生命周期
  ×4/collab/schedule×4/浏览器×N/计算机等）；descriptions 45 文件外置（改描述零
  ts diff）；工具契约含 sideEffectScope/needsApproval/prepareApproval/riskLevel/
  executionMode/timeoutMs；ToolRegistry 支持 spill 配额/gc/read-gate 记账/
  background shell/PathGuard 写边界。
- **判定**：规模与治理面 **aegent 数倍于 pi**（这是产品定位差异：aegent 的工具
  面含浏览器/计算机/调度/记忆/查询等平台级工具）；pi 的 **Operations 后端可整体
  替换**接口形状更干净（我方走的是 sandbox backend + env 注入的等价路线，但
  没有工具级 Operations 抽象那么整齐）。

### 3.4 权限与审批（差距最大的一节）

- **pi**：**没有权限/审批子系统**。事实上的两层：ProjectTrust（按项目路径持久化
  信任决定，未信任项目不加载任何配置/扩展/技能）+ 扩展 `tool_call` 钩子返回
  `{block, reason, terminate}`；"ask"语义由扩展自己弹 UI 实现（官方给的是示例
  代码）。没有 allow/deny 规则持久化、没有审批竞速、没有第二出口、没有超时
  结算语义。
- **aegent**（`src/policy/` 35 文件/4,996 行）：四层规则链（POLICY_LAYERS +
  不可跳层）+ 内置规则匹配器（危险命令/路径/网络语义）+ PermissionBroker 端口
  （Manual/Deny/允许表）+ **PendingApprovals 审批挂起注册表**（超时结算/超赛/
  状态机）+ **racePermissionResponders 审批竞速**（hook 慢/挂死不阻塞用户点击，
  先到者胜/败者 abort/全弃权 fail-closed——本轮修复了败者 rejection 吞收）+
  scope="always" 规则写回（原子+schema 往返校验+限层）+ 计划模式进出权限规则
  + 配置行级写回（保注释/原子/锁/TOCTOU 防线）。
- **判定**：**这是 aegent 相对 pi 最大的增量**。pi 的哲学是"权限交给扩展作者"，
  aegent 的哲学是"权限是内核契约"。代价是我方 policy 域 4,996 行 vs pi 的 0——
  但这也是多端产品（IM/无人值守/桌面）的安全底线所在。**pi 无对应物。**

### 3.5 扩展/插件

- **pi**：双轨——文件发现（`<cwd>/.pi/extensions/` + `~/.pi/agent/extensions/`
  + npm 包 package.json 的 `"pi": {extensions, skills, prompts, themes}` 字段）
  + SDK 直接传 ExtensionFactory。`ExtensionAPI.on(...)` 约 **40 种事件**（多数带
  Result 合并语义：block/替换 content/注入消息）；可注册
  tool/command/renderer/widget/keybinding/autocomplete。扩展=进程内 TS 模块，
  **无沙箱、无能力分片**，唯一门禁是 ProjectTrust。内置扩展 4 个
  （codemode/mcp/tool-search/llama）。
- **aegent**：manifest（plugin.json：name/trust/capabilities/hooks/theme）+
  claude 兼容映射 + scaffold 四模板；contributes 六类（tools/commands/skills/
  views/mcpServers/settings）+ W15b 三类（services/bus/telemetry）；**17 权限
  闭集 + 8 能力分片 + 贡献↔权限绑定校验 + 可用集单一事实源**（本轮修复后
  host 安装预检与子进程装载面同源）；热重载能力变宽即拒（上限快照）；
  inprocess/ws 双传输（ws 恒 untrusted + 工具登记白名单）；ServiceBroker
  （重启退避）+ PluginBus（topic 闭集+限流+deadline）+ TelemetrySink 三实现。
- **判定**：pi 的 40-hook 事件面**比我方宽**（我方 hooks.register 的事件集较
  小——message/turn 级为主），扩展作者体验 pi 更自由；aegent 的**治理面
  （权限闭集/分片/可用性校验/热重载上限/服务托管/总线/遥测）pi 无对应物**。
  这是"信任开发者（pi）vs 治理第三方（aegent）"的哲学分叉。

### 3.6 子代理与多会话编排

- **pi**：内核无子代理原语；官方姿势是**示例扩展 spawn 独立 pi 进程**（JSON
  模式，single/parallel/chain 三模式）；结构化 subagent/任务图/持久化调度在
  **实验性 durable 包**（与 coding-agent 平行的 chord 文档状态机事务化路线，
  未进主线）。
- **aegent**：内核级 subagent runner（深度检查/后台委托注册表/并发上限/steer
  /resume/task_send 定向投递/回投指引）+ **collab 编排方向盘**（七动作模型工具
  + 本地协作运行时 + 每父 4/全局 16 上限 + 环检测 DAG 纪律 + completion 回投
  幂等闸）+ jobs（owner 会话隔离 + epoch）+ cron/无人值守调度（offpeak 窗口
  + flush 确认 + 冷恢复 + 只补最近一次）。
- **判定**：**主线 pi 完全没有，aegent 全栈有**——这是两仓产品定位差异最大的
  面（pi 是单人 CLI 助手，aegent 目标是多会话编排平台）。pi 的 durable 包值得
  持续观察（事务化 harness + 存储一致性测试套是高质量设计，若其转正可对标）。

### 3.7 Provider 层

- **pi**（packages/ai，199 文件/27,242 行）：**41 家具名 provider / 10 种 wire
  API**，模型目录 `models.generated.ts` 数据生成 + 用户 models-store 覆盖；
  12 变体流式事件词汇表（text/thinking/toolcall 三族 × start/delta/end + done
  7 种 stopReason 含 deferred）；typebox schema 统一；credential-store + OAuth
  helpers；images/classifier 两条产品线；bedrock/vertex/azure 企业云全支持。
- **aegent**（src/models，13 文件/2,934 行）：3 个适配器（anthropic-messages/
  google-generate/openai-compat——兼容面覆盖 OpenAI 形状的全部中转）+ catalog
  + identity/健康探测/cache-health/fault-tolerance/retry/oauth。词汇表
  StreamChunk 闭集与 pi 同构（text/thinking/toolcall 三族）。
- **判定**：**provider 广度 pi 大幅领先**（41 vs 3 适配器形状）。我方的
  openai-compat 适配器实际覆盖了大量 OpenAI 形状中转（国内场景主路径），
  但 anthropic 的 cache 分块、google 原生 thought 等深度特性 pi 的分家适配器
  更精细。**这是我方最明确的取欠方向**（catalog 数据化生成尤其值得抄——
  我方 catalog.ts 是手写的）。

### 3.8 上下文压缩

- **pi**：内核只有 transformContext/convertToLlm 两个挂点；压缩在
  coding-agent 用 prepareRequest 钩子实现（阈值 reserve 16,384 + chars/4 估算
  + 切点优先 turn 边界 + 摘要写 compaction entry）。
- **aegent**：context 域内置 compaction（切点/摘要/预算/压缩事件落流）+
  projection 侧 prefix-anchor/result-trim/coalescer 等投影件。
- **判定**：同构。pi 的"压缩结果也是 entry（可审计可回放）"我方以 compaction
  事件落流等价实现。平手。

### 3.9 进程模型与协议

- **pi**：单进程为主（TUI 内嵌）；远程会话走 client/server + CBOR 二进制协议
  （PROTOCOL_VERSION=8，16MB 帧上限，typebox 严格校验）。
- **aegent**：**1 会话 1 child 进程**（agent-child stdio JSON-RPC + 正式入口
  dist/src/runtime/child.js）+ host WS/IM 服务面 + 便携打包 + win32 沙箱
  helper（受限令牌）+ Tauri 桌面 + 签名更新。
- **判定**：pi 的 CBOR 帧协议比我的 JSON-RPC 带宽效率高（但复杂度也高）；
  我方的进程隔离/沙箱/签名分发是 pi 完全没有的工程面（pi 信任本机用户）。

## 4 · aegent 有、pi 没有（我方增量清单）

1. 权限/审批全栈：四层规则链、broker、竞速第二出口、规则/配置写回（§3.4）。
2. 内核级子代理 + collab 编排 + jobs/cron/无人值守（§3.6）。
3. 插件治理：manifest/能力分片/权限闭集/可用性校验/热重载上限/服务 broker/
   总线/遥测（§3.5）。
4. SQLite 事件源的崩溃语义：commit 原子批、write-behind 串行 + seq 断言、
   ignorable 信封 fail-closed（§3.2）。
5. 进程隔离与分发工程：1 会话 1 child、win32 受限令牌沙箱、Tauri 签名更新、
   便携布局（§3.9）。
6. 33 事件闭集 + C14 JSON 安全 + C16 穷尽断言 + E16 投影校验器——词汇表
   治理 pi 是开放类型（我方是封闭契约）。
7. 无人值守档位（ask-all→deny 转换）+ 会话配置热刷新白名单。

## 6 · 总结

- **内核单独可用：是。** 40,366 行内核全家 + 2,408 用例 + 真机冒烟 + 便携分发
  全链就绪，入口 `dist/src/runtime/child.js`。
- **对比 pi**：架构同宗（pi 是本次重构的第一对照原型——队列语义/压缩挂点/
  事件词汇表均以其为参照），但两仓在"信任开发者"与"治理第三方"之间做了相反
  的选择。aegent 在权限治理、编排、进程工程上大幅超出 pi；pi 在 provider 广度、
  schema 体系、扩展自由度、分支交互上领先。**没有一面对 pi 是"全面落后"**；
  最值得动手的取欠是 provider catalog 数据化（高）与两个低成本的循环细节
  （工具差量声明、截断整批拒绝）。
