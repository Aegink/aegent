# 插件系统对比与改造建议（2026-10-02）

> 调研阶段产物（用户规则：先报告后改码，A~X 方案分级交用户裁决，打勾后才实施）。
> 六路调研（3+3 两批并发，每批 ≤3 个 Explore）：批 1 深度 = pi-desktop / deepseek-harness(dsh) /
> zcode；批 2 = opencode / codex / 其余仓快扫（kimi-code、grok-build、pi、pi-mono、qwen-code、
> pideck、hermes-agent、agentscope、cc-switch、mini-agent、mini-swe-agent）。
> 域定义：**"插件" = 第三方/自己写的包，向宿主贡献能力（工具/命令/技能/主题/面板/hook/MCP/设置），
> 并覆盖其全生命周期（发现→安装→审批→启停→创建→更新→卸载→观测）**。
> 全部结论附 file:line（相对各仓库根）；调研代理产出、我方未逐条复核的锚点以原样收录，
> 不确定处已标【未验证】。

## 0. 结论一句话

参考仓的插件系统共同回答了三件事：**①插件能贡献什么**（pi-desktop 15 类 contributes 最全、
zcode 6 类组件最贴 CLI、dsh 用 cordis slot/service 让"万物皆可插"）、**②怎么创建**（pi-desktop
四模板脚手架 + zcode plugin-creator"agent 用工具按模板生成插件"是两条现成路）、**③怎么分发**
（codex/grok-build/zcode 三仓证实"git 仓库 + marketplace.json 索引 = 市场"，无需服务端）。
我方已有地基比多数仓更严（trust 分轨 + 安装期 fail-closed 校验 + never-fail 装载 + 主题即插件），
但**贡献面只有 工具/hooks/主题 三类、零模板创建、零市场、插件页只是设置页里一个分节**。
改造主体：manifest v2（contributes 形状）+ 四模板脚手架 + agent 创建工具 + git 市场 +
插件页独立成页（已安装/市场/创建 三 tab + 详情 + 审批）。

## 3. 参考仓要点

### 3.1 pi-desktop（重点仓 1：贡献面最全 + 四模板 + catalog 市场）

- **contributes 15 类**（`packages/plugin-sdk/src/index.ts:91-146`）：panel/views/commands/
  agentTools/skills/agentExtensions/providers/settings/themes/scenicThemes/windowAppearance/
  mcpServers/services/bus/globalShortcuts/sessionSources；声明式 + 运行期动态注册双通道，
  宿主统一 dispatch（`apps/desktop/electron/main/plugin-runtime.ts:1779-1787`）+ API 白名单
  （`plugin-runtime.ts:453-534`，≈90 项）。
- **manifest**（`index.ts:49-163`）：schemaVersion/id/name/version/main 必填 + i18n/
  author/engines/ui/contributes/permissions(36+ 闭集)/fs{read,write,delete 范围}/net.domains；
  三层校验（TS validateManifest+validateContributions、Rust 安装校验 928 行、devkit check 预检）。
- **审批模型**：权限三级风险表（`apps/desktop/src/features/plugins/model.ts:39-78`）+ 安装前
  审查对话框（`PluginDialogs.tsx:96-140`）+ dev 两步加载（loadDev→Confirm，
  `ipc/plugin-ipc.ts:160-187`）+ **热重载天花板**（以批准时快照为上限，变宽即拒，
  `plugin-runtime.ts:1949-1993`）+ fs 越界一次性原生同意（once/session/deny）。
- **四模板**（`packages/plugin-devkit/src/templates.ts:6-11`）：panel-basic / agent-tool-basic /
  skill-pack / full-demo（并集 + 最小权限示范 `fs:{write:{scope:["out/**"]},delete:{own:true}}`，
  templates.ts:186-225）；`scaffold()` 拒绝非空目录、id 默认 `local.<slug>`（84-111）。
- **CLI**（`cli.ts:8-18`）：init|create / check / pack / publish；pack = store-only zip
  `.piplug` + sha256（`pack.ts:151-156`）；publish = git 钉定（origin 规范化拒凭据 + 干净
  工作树 + tag/commit + 相对路径）产出 submission.json（`publish.ts:95-168`），本地不上传、
  语义是"提交中心重建比对"；walk.ts 强制剔除凭据文件（`.env*`/`*.pem`/`*.key`）。
- **市场 = HTTP catalog.json，不是 git clone**（`crates/host-core/src/plugins/marketplace.rs:11-23`
  三渠道 + GitHub raw 备份即"仓库托管 catalog + release 资产"形态）：条目带
  shasum/url/sizeBytes/permissions（装前可渲染权限审查）+ yanked/provenance/review/signature
  （`model.rs:318-357`）；verified 徽章只认官方（marketplace.rs:660-696）；auto-update 拒绝
  静默扩权（install.rs:254-257）；镜像防跨源 artifactBaseUrl（marketplace.rs:218-245）。
- **隔离**：每插件一个 utilityProcess，child 零宿主能力、`pi.*` 走 JSON 帧代理回 broker
  （`plugin-host-process.mjs:10-19`）；分级超时 load 15s/hook 5s/tool 110s；崩溃指数退避
  重启 ≤5 次（plugin-runtime.ts:2799-2843）。
- **UI 全链**：PluginsPage 双 tab（`pages/PluginsPage.tsx:123-145`）+ 渠道四选项下拉
  （`MarketplaceSourceSettings.tsx:69-109`）+ 分类 tag + 下载次数 + 认证徽章 +
  安装进度逐阶段推送（resolve→download→verify→install→enable）+ 详情 sheet。
- **捆绑插件同通道**（ADR 0104）：`apps/desktop/resources/plugins/` 的 pi.browser/pi.file-manager
  与第三方完全同一贡献通道、不可卸载只能停用（`registry.rs:86-181`）。
- **示例插件**：`examples/plugins/hello`（贡献面最全活样例）+ roundtable（纯工具+技能型）。

### 3.2 deepseek-harness / dsh（重点仓 2：cordis 万物可插 + 动态插件）

- **关键定性**：dsh 有两套插件面——**持久 bundle**（pnpm 装进 profile、Loader patch 分层组合，
  Plugin Manager 页管理它）+ **动态插件**（agent 现场写码、用户审批、重启即丢；
  `packages/extensions/cordis-host-runner/README.md:9`）。信任级别与审批路径各自独立。
- **cordis 运行时**（vendor/cordis，koishi 系）：插件 = 实现 Service 的对象、Context = 服务
  仓库、`inject` 声明依赖（服务可用性驱动装载顺序，无手工 boot 序）、五种事件派发模式、
  注册皆可逆 effect（`vendor/cordis/src/fiber.ts:184` fiber 反向回收）。
- **UI 贡献 = slot 系统**（`packages/client/ui-slots/src/index.ts:101` 四种 cardinality
  single/list/keyed/chain + SlotMap 声明合并 + 生成器产出 3972 行编译期契约目录
  `slot-catalog.ts:12`——插件不读源码即可正确注册；预置槽位如 sidebar.footer.action/
  tool.call.toolview/conversation.composer.dock）。
- **动态工具防伪造**：`harness.defineTool` 打 `DYNAMIC_TOOL` 标记、`registerTool` 只收带
  标记定义（`cordis-host-runner/src/guard.ts:495-499`）；跨 realm cloneJson 深拷贝；沙箱
  ctx 只放行"自己声明过的 inject"（guard.ts:701-744）；官方自述"API discipline, not a
  security boundary"（`cordis-client-runner/src/client/guard.ts:11-13`）。
- **审批**：动态插件带 Client 半段须面板批准（可勾"以后都批"）；`plugin_manager` 每动作
  强制 danger-full-access 逐次审批（`packages/boot/plugin-manager/src/tools.ts:34-40`）。
- **"按模板创建"的 dsh 形态 = Agent 技能 + 手写模板**（decoration/mcp 两模板，
  `skills/cordis-plugin-development/templates/`）；`scripts/gen-plugin-packages.ts` 是清单
  生成器（生成"哪些包可装载"目录）**不是**脚手架（开工提示词 §2 的表述已纠偏）。
- **故障隔离**：fiber 即隔离域；渲染崩溃 onEntryError 归因到包并 abdicate 条目 + steer 回会话
  （`cordis-host-runner/src/index.ts:1024-1119`）。
- **参考价值**：三层插件面分工（只读 inspect / 动态定义 / 持久 bundle）+ slot 契约目录 +
  "动态代码复用宿主完整生命周期" + 教学式报错（每次失败自带修复指令）。

### 3.3 zcode（重点仓 3：六类组件 + git 市场完整链路 + plugin-creator）

- **manifest**（`contracts/src/plugins/index.ts:141-161`）：三目录兼容
  （.zcode-plugin/.claude-plugin/.codex-plugin）；组件 = skills/commands/agents/hooks/
  mcpServers/dependencies/userConfig（required/sensitive/type）+ 展示元数据；
  不支持的键（channels/lspServers/outputStyles/settings）只发 diagnostic 不拒装。
- **市场七来源**（`marketplace.ts:66-75`）：url/github/git/npm(识别不支持)/file/directory/
  settings 内联；用户输入解析 shorthand（`owner/repo#ref`→github 等，marketplace.ts:221-268）。
- **权威状态文件**：known_marketplaces.json + installed_plugins.json +
  `marketplaces/<mp>/marketplace.json` 快照 + `cache/<mp>/<plugin>/<version>/` +
  `data/<id>/`（marketplace.ts:47-143, 2629-2647）；官方市场 = bundled seed 分片 + CDN 分片
  合并（`official-marketplace.ts:63-86`）。
- **安装链**：依赖闭包解析（跨市场白名单 + 环检测）→ 原子目录激活（staging+backup+
  transactionId，`atomic-directory.ts:58-120`）→ installed_plugins.json → 默认启用写 config；
  git 源 = `--depth 1 [--branch ref]` + 3 次重试（marketplace.ts:1410-1431）；GitHub 源优先
  zipball（`github-archive-source.ts:77-153`）；zip 源强制 64 位 hex sha256。
- **plugin-creator**（`bootstrap/src/app/official-plugin-definitions.ts:245-275` + 本机缓存
  SKILL.md）：六步 = 定义产出 → 创建实现（plugin.json + 仅所需组件文件）→ 环境可验证检查
  （占位符/路径逃逸/symlink/JSON）→ 准备本地测试市场（`upsert-dev-marketplace.mjs`：稳定
  dev 名 `dev-<label>-<sha256(path)[:8]>` + atomic JSON + lock）→ 指导用户 UI 操作（agent
  不代劳安装）→ 如实交付；脚手架含最小 MCP stdio 握手骨架。
- **信任面**：安装无审批（除 CLI 卸载确认）；**plugin hooks 恒放行**（`canRunPluginHooks`
  恒 true，`index.ts:366-371`，注释明示升级路径）；路径必须 `resolveInside`、不跟随 symlink；
  命名空间隔离（MCP `plugin:<name>:<server>`、同名 enabled 插件 fail-closed 冲突标记、
  用户/项目命令优先于插件命令）。
- **UI**：PluginStorePage（public/personal 分段 + Featured + 分类折叠）+ 源管理对话框 +
  详情（组件分组、可离线读缓存）+ 商店"创建插件"把 plugin-creator skill 预填进新任务
  （`pluginCreatorPrefill.ts:8-31`，只信官方 id 防同名截获）。

### 3.4 codex（git 市场双层模型 + git 安全细节最全）

- **定性**：插件 = 声明式资源包（skills/MCP/apps/hooks/UI 元数据），唯一执行通道是声明的
  MCP server 与 hooks；manifest 三层兼容（plugin.json / .codex-plugin / .claude-plugin /
  .cursor-plugin，`plugin_namespace.rs:43-80`）。
- **双层模型（重点）**：市场本身是 git 仓库（clone 进 `.tmp/marketplaces/<name>`），
  marketplace.json 只是索引（`.agents/plugins/marketplace.json` 等四选一，
  `core-plugins/src/marketplace.rs:20-25`）；**每个插件条目自带独立 source**
  （`local|git{url,ref,sha,subdir}|npm`，marketplace.rs:127-143）；安装 = 物化来源 → 拷入
  版本化缓存 `plugins/cache/<marketplace>/<plugin>/<version>`（store.rs:26）→ 运行永不依赖
  源仓库；git-subdir 支持 sparse checkout（`loader.rs:1818-1876`）。
- **原子安装**：staging tempdir → 复核 manifest 字节未篡改 → rename 激活 → 删旧版本 → 失败
  backup+rollback（store.rs:605-742）。
- **git 安全（照抄清单）**：移除 17 个 `GIT_*` 环境变量、`safe.bareRepository`、受信任临时
  GIT_DIR 防 cwd 仓库劫持、`GIT_TERMINAL_PROMPT=0`、全部 git 命令 30s 超时 kill、sha pin 后
  `rev-parse HEAD` 复核、企业白名单在 clone **之前**拦截（`git_policy.rs:7-85`、
  `marketplace_policy.rs:34-103`、loader.rs:1889）。
- **更新**：`git ls-remote` 拿远端 revision 与 config `last_revision` 比对，一致跳过
  （`marketplace_upgrade.rs:241-294`）——不盲目重 clone。
- **故障隔离**：单插件错误进 `LoadedPlugin.error`（`is_active = enabled && no error`，
  load_outcome.rs:31-33）；启停存 config.toml `[plugins."x@y"] enabled`（toml_edit 原子写）。
- 官方市场 `https://github.com/openai/plugins.git` 启动同步（startup_sync.rs:23-38）。

### 3.5 批 2 其余仓（快扫结论）

- **grok-build**（Rust，claude 同构 + git 官方市场）：manifest 容错链
  plugin.json→.grok-plugin→.claude-plugin + 约定目录兜底（`plugins/manifest.rs:1-9`）；
  **官方市场就是 git 仓库** `xai-org/plugin-marketplace`（首跑自动注册，
  `xai-grok-plugin-marketplace/src/lib.rs:26-29`）；**信任分级**：per-plugin-root trust store
  （`~/.grok/trusted-plugins`），不受信插件的 skills/agents 只列元数据、hooks/MCP/脚本全阻止
  （`plugins/trust.rs:1-13`）；git 安装支持 `user/repo@ref#subdir` 简写。
- **kimi-code**：自研 `kimi.plugin.json` + 自建市场 marketplace.json（tier: official/curated，
  source 支持本地/GitHub URL/release zip 直链）+ TUI /plugins 信任确认（官方隐式信任、其余
  强制 trust prompt，`apps/kimi-code/src/tui/commands/plugins.ts:454-455`）；收录 claude 生态
  插件。

### 3.6 跨仓共同模式 Top 3（直接支撑本卡需求）

## 4. 与"插件"这个词的差异定位（需求第 6 条）

参考仓克隆不可取之处与我们的差异主张：

1. **不做"zcode 式 CLI 贡献物克隆"**：zcode/codex 的插件本质是静态资源包（skills/commands/
   hooks 清单），运行期贡献少。我方已有**运行期插件 SDK**（受限能力 token + 生命周期 + 事件
   投递），插件是活的代码——这条路线 dsh/pi-desktop 同款，继续走深（contributes 静态声明 +
   运行期动态注册双通道，pi-desktop 同构）。
2. **信任面比参考仓严**（多数仓明弱：opencode 零权限声明、zcode plugin hooks 恒放行、codex
   无签名无审批）：我方保留 trust 分轨 + fail-closed 安装校验，并新增审批/降级面（Q/S）——
   严信任是差异点不是包袱。
3. **万物可插的"物"以宿主现有域为坐标系**：工具（已有）、hooks（已有）、主题（已有）、
   技能（技能域）、命令（提示词模板/自定义命令域）、MCP（MCP 域）、面板/视图（UI 域新增
   slot）、设置（插件详情表单）——插件是这些域的第二作者入口，而不是独立平行系统。
4. **"0+"**：零捆绑特权——宿主自带可插能力也走同一清单/装载/审批通道（pi-desktop ADR 0104
   同款），示例插件以"可卸载的普通插件"形态内置（W）。

### 第一波：贡献面（万物可插件的地基）

  same-origin/脚本受控）+ postMessage 桥（窄消息面：主题 token / 打开视图 / 关闭），不进
  dsh 式同 realm React（我方 UI 是 vanilla JS，iframe 是同构最小面）。参考：pi-desktop
  views 声明（`index.ts:137,629-640`）+ `plugin-view-host.ts`；dsh slot cardinality 思想

  只读快照 + 主题 token）；验证：示例插件视图渲染/主题跟随/卸载即消失。
- **D.☆ 技能贡献**——contributes.skills（目录或文件）→ 进技能域发现（instructions-gateway

- **E.☆ MCP 服务器贡献**——manifest.mcpServers → 进 MCP 域（现有 MCP 页 v2 的外部配置

### 第三波：git 市场

- **K.★ 市场模型**——`plugins/marketplace.json` 索引格式：
  `{name, description?, plugins:[{name, source, description?, version?, tags?, category?}]}`
  ；市场来源 v1 = **local（目录）/git（URL，可带 ref/sha/#subdir）** 两种（npm/remote 留
  v2）；`owner/repo#ref` shorthand 解析；条目 source 支持 `./相对路径`（monorepo 子目录）。
  参考：codex 双层模型（`marketplace.rs:127-143` + 条目 source 1009-1044）；zcode 来源
  解析 shorthand（`marketplace.ts:221-268`）；grok-build 官方市场=git 仓库先例
  （`lib.rs:26-29`）。落点：src/host 新模块 plugins-marketplace（注意行数纪律拆文件）。
  验证：添加一个指向真实 git 仓的市场 → 列出插件。
- **L.★ 安装链**——市场装插件 = 解析条目 → 物化 source（git：depth-1 clone [+sparse]；
  local：原路径拷贝）→ 安装期校验（复用 validateManifest fail-closed）→ staging → 原子
  rename 激活进 `~/.aegent/plugins/cache/<marketplace>/<plugin>/<version>/` → 权威记录
  installed_plugins.json → settings.plugins 登记。卸载 = 删缓存 + 清记录（内置示例走
  suppression 软删可恢复，可选）。参考：zcode 原子激活（`atomic-directory.ts:58-120`）+
  权威记录（marketplace.ts:125-143）；codex staging→复核→rename→backup（store.rs:605-742）。
  风险：Windows rename 语义/文件占用（失败回滚路径必须真实可用）；验证：装/更/卸全链 +
  断网中途失败回滚不落半成品。
- **M.★ git 安全细节**——GIT_* 环境消毒（17 变量清单）、`GIT_TERMINAL_PROMPT=0`、子进程
  30s 超时 kill、sha pin 后 rev-parse 复核、白名单策略位（可选 restrict）、更新 =
  ls-remote revision 比对（一致跳过）。参考：codex `git_policy.rs:7-85` +
  `marketplace_upgrade.rs:241-294`。验证：单测环境变量净化 + 假 sha 拒装。
- **N.★ 市场 UI**——插件页"市场"tab：市场源管理（添加/刷新/移除 + 上次刷新时间/失败

  更新检查（K 的 last_revision 轴）。参考：zcode PluginStorePage + 源管理对话框（§3.3 UI
  清单）；pi-desktop MarketplacePanel（分类 tag/徽章/安装按钮，§3.1）。验证：机器等效
  走查（加源→刷→装→更→卸）。
