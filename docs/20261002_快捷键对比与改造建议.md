## 0. 结论一句话

参考仓共同把"快捷键"做成**五个域**：①键位模型（声明式叠加规则+chords+when 上下文，
非"快照覆盖"）②GUI 编辑器（四列行+录制改键三步流+来源分层+冲突可见化+录制搜索）③
命令空间互通（命令面板每行显键位+面板内改键入口——键位域是命令空间的键盘视图）④
方案化（keymap profile/预设包整体切换/导出导入）⑤速查与发现（? 面板/hover 键位/
就地提示）。我方现状只有域②的最小链（9 动作+kbd 胶囊+捕获改绑+冲突提示）——"一个
页面就一个功能"的根源在此：动作面窄（8 个路由动作）、模型是覆盖快照非规则叠加、无
chords/when/方案/速查面板、键位与命令空间完全脱钩。改造主体：动作面扩到全应用命令
空间 + 规则叠加模型 + 四列编辑器 + 录制搜索 + ? 速查面板 + 键位互通。

## 2. 我方现状（本地源码深读）

### 2.1 引擎现状（ui/keymap.js 全集）

- **动作面 9 个**：settings/find/search/close-find/history/work/usage/notify 八个可
  绑定 + send 固定（Enter 核心交互不进自定义面）——全部是"面板开合/搜索类"路由
  动作；会话内动作（发送/换行/清空/中断/compact）、导航动作（对话页直达）等均不在
  命令空间。【本地源码】keymap.js:23-45
- **键位模型 = 覆盖快照**：settings.shortcuts（action→combo 串）部分覆盖 DEFAULT_
  KEYMAP——"用户层只存覆盖"这点与 VS Code 一致，但**无 when 上下文、无 chords、
  无卸绑规则（remove=清空覆盖回默认，没有"-command"式的显式卸绑）、单 action 单键位**。
- **冲突检测**：注册表内同 combo 冲突（阻断保存）+ RESERVED_COMBOS 浏览器保留键提示
  不拦截（keymap.js:48-61,101-109）。
- **事件分发**：resolveAction 全局 keydown 捕获；输入区内只放行带修饰键组合+Escape
  （app.js:1745-1756）——**when 语义的最小先例已存在**（inInput 就是一种 when）但
  硬编码不可配置。

### 2.2 UI 现状（system.js shortcuts 分节）

- 行式清单：搜索过滤（label/action 匹配）+ 每行 kbd 键帽胶囊 + 「修改」捕获态
  （按新组合即显，Esc 取消）+ 冲突/保留键行内提示 + 「恢复默认键位」。
- 捕获改绑**即改即存**（捕获完成直接落 settings.shortcuts——无 VS Code 式"Enter
  确认才落盘"）；无录制搜索、无来源列（默认/自定义不可辨）、无重置单行（只有全局
  恢复默认）。

### 2.3 差距小结

引擎有：规范化/冲突/保留键/部分覆盖。UI 只有：9 行改绑清单。**动作空间与全应用
命令脱节（发送/新会话/复制/滚动等不可键位化）、无 chords（Ctrl+K 系）、when 硬编码、
无录制搜索（"这个键现在干什么"查不了）、无单行重置/来源标注、无 ? 速查面板、无键位
方案与预设包、配置包 transfer 已含 shortcuts 但无独立导出视图。**

## 3. 参考仓调研

### 3.1 VS Code（官方文档全域深读——键位域最全先例）

**A. keybindings.json 体系**（【官方】code.visualstudio.com/docs/configure/keybindings）

- 三层叠加：默认+扩展+用户 keybindings.json，运行时**追加到末尾、后声明胜**。
- 规则字段：key/command/when/args（2026 新增 systemWide——OS 级全局热键）。
- **负向绑定**：`-command` 卸绑规则（args 可精确匹配只卸某条）；空串卸绑 v1.78 已失效。
- 一个命令可多键位；`runCommands` 一键多命令；Ctrl+K Ctrl+K 在 JSON 编辑器内就地
  录制键串。

**B. when 子句**：【官方】when-clause-contexts——上下文键（inputFocus/editorFocus/
terminalFocus/listFocus/inQuickOpen…）+ 操作符全集（!/==/&&/||/=~/in/config.xxx）；
同一键不同上下文绑不同命令；我方 inInput 是 when 的最小硬编码先例。

**C. chords**：两段式（"ctrl+k ctrl+s"），第一段命中进 pending 等第二段，**无超时**
Esc 取消；默认命令大量使用（Ctrl+K Ctrl+S 打开键位编辑器等）。

**D. 键盘快捷键编辑器 GUI**（重点）：模态浮层形态；**搜索双模式**（文本多字段+Record
Keys 录制搜索——按"这个键现在干什么"的第一入口）+ 过滤器语法（@command/@keybinding/
@source:user）；**行内四列**（命令/键位/when/来源 Default|User|扩展）；改键三步流
（双击/铅笔→"按下组合键然后按 ENTER"→Enter 确认 Esc 取消，确认前不落盘）；右键菜单
（Remove=写 -command 卸绑 / Reset=删覆盖 / Show Same Keybindings=冲突定位 / Change
When Clause）；被覆盖默认键位保留显示+来源标注；按 precedence 排序。

**E. 方案化**：Profiles 组件含 keybindings（不含时回退 Default Profile）；导出 Gist/
本地文件；Settings Sync 类目含 Keyboard Shortcuts；keymaps 扩展生态（JetBrains/Vim/
Emacs/Sublime 预设包整体切换）。

**F. 命令面板耦合**：Ctrl+Shift+P 是"最重要组合键"；面板每行右侧显当前键位+齿轮改键
（v1.52 起）+hover 显键位（v1.140）；MRU 置顶可键盘跳转可移除；**面板与键位域是同一
命令空间的两个视图**。

**G. GUI 借鉴清单**（调研代理产出，10 条）：双层双视图（GUI+JSON）/搜索双模式/四列
行信息密度/冲突可见化/三步改键确认前不落盘/Remove 与 Reset 语义分离/声明式叠加/
方案化预设包/面板键位互通/when 即焦点区域感知。

### 3.2 Zed keymap（官方文档+源码——键位即一等配置+渐进揭示先例）

**A. 文件体系与叠加**（【官方】zed.dev/docs/key-bindings + 源码 keymap_file.rs）

- 默认键位按平台三文件（~1700 行）+ **base_keymap 预设作独立 overlay 层**（VSCode/
  JetBrains/Emacs/Atom/Sublime/Cursor/None 九选一，v1.14.2 重构为 overlay）+ 用户
  keymap.json（后加载必胜）；**保存即热重载**（watch_config_file，main.rs:437）。
- 叠加语义：**上下文树更深层匹配者胜**（Editor 内绑定优先于 Workspace 级）→ 同深度
  后定义者胜；单条解析失败不拖垮整个 keymap（#23113 容错）。

**B. 规则模型**：section = context（when 式谓词，支持 &&/||/!/()/祖先算子 `X > Y`，
属性 os/extension/vim_mode 等）+ bindings（**任意段数按键序列**——"cmd-k cmd-s"、
"shift shift" 双击修饰键也合法）+ **unbind 显式解绑表**（v0.229.0——GUI 删除默认
绑定生成 unbind 记录而非写死覆盖）+ 带参 action（单参/对象参）+ SendKeystrokes 键宏
（上限 100 键）。

**C. action 空间**：内置 action **1409 个**（all-actions 页实测），17+ 命名空间；
命令面板即 action 模糊搜索入口，条目旁内联显键位+**左下角 Change/Add Keybinding
直达改键**。

**D. GUI 编辑面**：Keymap Editor（cmd-k cmd-s）——列全部 action+默认绑定、行内
铅笔/双击/回车编辑、**按键录制**、Search by Keystrokes（按按键搜）、录制独立修饰键；
GUI 写回 keymap.json（单一事实源）。用户改键三层递进：**GUI 轻改 → JSON 细配 →
预设 base_keymap**。

**E. 发现四通道**：命令面板内联键位（禁用态**变暗而非隐藏** #27693）/ 状态栏 pending
指示器（多段键等待候选+**倒计时**+hover 暂停 #63343）/ **which-key 菜单**（v0.219.4
——按前缀键延时弹候选面板，delay 可配可关 #43618）/ Keymap Editor 本身即可搜索
速查表。无 ? 全局 cheatsheet。

**F. vim/helix 模式**：内置（非扩展）——vim.json 1301 行键位层，覆盖机制=mode
context（vim_mode == normal|insert|visual + waiting/operator 状态）；扩展**不能贡献
keymap**（#8829 提案至今未实现）。

**G. GUI 借鉴清单**（调研代理产出，8 条）：预设 overlay+用户覆盖+单一 JSON 事实源
三层架构/双向检索（按命令名搜+按按键录制搜）/每条绑定展示 context 作用域/冲突与
pending 显式 UI（前缀冲突提示+倒计时）/which-key 式渐进揭示/禁用态键位提示变暗/
删除≠写死覆盖（unbind 记录）/发现三通道+当前作用域实时视图。

### 3.3 opencode keybinds + pi /hotkeys（GitHub 源码——agent CLI 同类键位面）

> 勘误【官方】：sst/opencode 重定向 anomalyco/opencode（dev 分支）。

**A. opencode keybinds**（【官方】tui keybind.ts + app settings-keybinds.tsx）

- 配置在 **tui.json**（opencode.json 的遗留 keybinds 键会被加载器显式删除）；
  **184 个可键位化命令**（183+leader）；键形状=字符串（逗号分隔多键）/数组/对象
  （preventDefault/fallthrough）/`"none"` 显式禁用；未知键名报错。
- **leader 键机制**：`keybinds.leader` 独立项（默认 ctrl+x）+ 键位串 `<leader>` 占位
  引用 + leader_timeout 2000ms；registerTimedLeader 进入 pending 等下一键，**Esc 取消
  pending、Backspace 回退一层前缀链**——Vim 风格"前缀+单键"（`<leader>q/n/y/1..9`），
  规避终端与输入法冲突。
- **which-key 面板**（feature-plugins/system/which-key.tsx）：手动开关 ctrl+alt+k +
  **pending 自动浮现**（overlay 布局+pendingPreview 时按 leader 即显示下一跳候选）+
  分组多列多 tab+可 pin 常驻。
- **桌面/Web 应用有完整 Settings→Shortcuts 页**（settings-keybinds.tsx）：6 语义分组
  +fuzzysort 搜索+点击进入按键捕获重绑+Backspace/Delete 清绑为 none+**冲突 toast
  拒绝**+resetAll——与我方同类页的最直接同类先例。TUI 无改绑 UI（纯配置文件，改后
  需重启）。命令面板每条右侧实时显当前键位。

**B. pi /hotkeys**（【官方】interactive-mode.ts + keybindings.ts）

- `/hotkeys` = 往聊天区插入 Markdown 表格面板（Navigation/Editing/Other/Extensions
  四组），**实时解析当前生效绑定**（含用户自定义），只读不可改；"the best source of
  truth"。
- keybindings.json（agent-dir）：动作 ID→键串/数组，**用户值整体替换默认**，`[]`
  禁用；**90 个可键位化动作**（tui.editor.*/app.session.* 等命名空间）；/reload 手动
  热重载；旧名自动迁移。
- **常驻 hint 系统**：keyHint(键位, 说明)——界面各处内联"暗色键名+说明"（菜单/按钮
  旁显键位的先例）。
- 优先级规则明文：历史动作优先于同键应用动作；全屏 transcript 动作优先于编辑器动作
  ——when 分层的同类先例。KeybindingConflict 数据模型（getConflicts）有但 UI 未消费。

**C. GUI 借鉴清单**（调研代理产出，6 条）：列表+搜索+分组只读总览先行/点击即捕获
（全局拦截 keydown+Esc 取消+Backspace 清绑）/改绑即时查重 toast 冲突对象名/速查面
与改绑面分离（速查实时反映生效键位）/leader 前缀+pending 自动预览+超时可配/禁用
用显式哨兵值+一动作多键+平台差异集中声明。

### 3.4 JetBrains keymap（官方文档+源码——方案化与冲突治理先例）

**A. 方案体系**（【官方】jetbrains.com/help/idea + 源码 intellij-community）

- 内置方案十套（$default/GNOME/KDE/XWin/Emacs/Mac 系/Sublime）+ 捆绑插件方案十套
  （Eclipse/VSCode/Xcode/VS2022/ReSharper…）；**方案=以 parent 为根的差异覆盖**
  （XML 头 `parent="$default"`，macOS System Shortcuts 挂在 Mac OS X 10.5+ 下成链）。
- **预置只读+改动即 fork**：改预置方案自动"create a copy"，副本缩进挂在父方案下；
  方案级操作四件套 Duplicate/Rename/Delete/Restore Defaults；继承项显 "inherited
  from" 链接（改父更新子、改子断继承）。
- 切换：Settings 下拉 + **Quick Switch Scheme 弹层（Ctrl+`）**——键位与主题/配色同
  弹层快速切换。

**B. 存储**：自定义方案=配置目录 keymaps/*.xml，**文件只含相对父方案的 diff**——
拷文件即导出/迁移/分享，天然可版本管理；Settings Sync 云同步类目含 keymaps。

**C. Keymap 设置页 GUI**（重点）：

- 搜索框（按动作名/双修饰键过滤+搜索历史）+ **Find Action by Shortcut 录键反查**
  （按目标组合列全部绑定动作；空结果=被 OS 拦截——同时是诊断工具）；动作树分组+
  展开折叠。
- **Add Keyboard Shortcut 录制式输入**：直接按真实按键即时回显，**同一对话框就地
  显示冲突警告**；确认时冲突二选一 **Remove（从另一动作移除）/ Leave（共存）**
  【社区·未验证】——**一键多动作合法**（"by design，动作在不同上下文生效"——冲突
  从错误重新定义为可解释的多绑定）。
- 右键菜单：Add/Remove Keyboard Shortcut / Add Mouse Shortcut（录制点击滚动手势）/
  **Add Abbreviation**（缩写别名——无键位动作经别名在 Find Action 可搜）/
  **Reset Shortcuts**（还原方案初始值）。
- **双修饰键手势**一等公民：double Shift（Search Everywhere）/double Ctrl，XML 用
  keyboard-gesture-shortcut，可全局禁用；**Second stroke 复选框**定义两段 chord
  （Emacs 方案 138 条 shortcut 大量 Ctrl+X 系）。
- macOS 专属 **Show conflicts with system shortcuts**（与 OS 热键冲突一键检查列表
  ——系统级冲突诊断）。

**D. 动作空间**：数千个（2026 YouTrack 明言）；平台默认方案 $default.xml 422 action
/443 keyboard-shortcut/14 mouse-shortcut/2 gesture——运行时列表随插件增长；动作 ID
体系（$Redo 核心/驼峰平台/点分命名空间插件）。

**E. GUI 借鉴清单**（调研代理产出，6 条）：预置只读+自动 fork/录制式输入+冲突现场
裁决（Remove/Leave）/双向查找（名称+录键反查，一键多动作合法化）/diff 存储（方案
即文件）/缩写别名+搜索结果就地改键（Alt+Enter）/系统级冲突诊断。

### 3.5 速查面板快扫 + gemini-cli/qwen vim 模式（Web 应用与 agent CLI 键位发现）

**A. 四家速查面板**（【官方】各文档+【社区·未验证】形态细节）

- **GitHub**：`?` 呼出**上下文感知模态**——只列"当前页面可用"键位（站点级含 `g c`/
  `g i` g 前缀跳转链），按页面上下文分组；面板无搜索（搜索由独立 Command Palette
  补位）；设置可**关闭字符键快捷键**（? 呼出与输入冲突的官方解法）。
- **Linear**：Cmd+/ 或 ? 开全量 overlay；**G 前缀导航链**（G I 收件箱/G T triage/
  G C cycles）+O 前缀打开链——两键序列撑起大量键位且不占修饰键；Cmd+K 命令菜单
  与速查互补。
- **Slack**：Cmd+/ 对话框=**顶部搜索框+tab 分类**（Messaging/Files/Workspaces/
  Marking）。
- **Notion**：Cmd+/ 已被块编辑占用→**无应用内速查**（反面教材——呼出键必须避开
  已有语义）。
- 共同模式：呼出键两派（`?` 单键 vs Cmd+/）；速查（发现/记忆）与命令面板（搜索/
  执行）双轨互补。

**B. gemini-cli / qwen-code**（【官方】文档）

- gemini-cli：readline 输入编辑全集（C-a/e/k/u/w/P/N/R）；**vim 模式**（/vim 或
  settings general.vimMode 持久化）——NORMAL/INSERT 两模式+计数（5j）+操作符组合

## 4. 参考仓共同模式（五路归纳）

1. **键位模型=声明式叠加规则**（VS Code 后声明胜/Zed 树深度优先+后定义胜/JetBrains
   父链 diff/我方部分覆盖同方向）——用户层只存覆盖，升级不毁自定义；**卸绑用显式
   哨兵**（VS Code `-command`/Zed unbind 表/pi 空数组/opencode "none"），不用删除。
2. **动作空间=全应用命令注册表**（Zed 1409 action/JetBrains 数千/opencode 184/
   pi 90）——键位页是命令空间的键盘视图，动作可分组可命名空间化；键位与命令面板
   互通（面板显键位+面板内改键）。
3. **GUI 编辑器三要素**：四列行（动作/键位/作用域 when/来源徽标）+ **录制式改键**
   （点击进入捕获态→按下组合→Enter 确认才落盘，Esc 取消）+ **录制搜索**（按按键
   反查"这个键被谁占了"——VS Code Record Keys/Zed Search by Keystrokes/JetBrains
   Find by Shortcut 三家同构）。
4. **冲突治理现场化**：录入时就地显示冲突警告+裁决（JetBrains Remove/Leave、
   opencode 冲突 toast）；一键多动作合法化（"不同上下文各有动作"——when 分层使
   冲突成为可解释状态而非错误）。
5. **发现三通道**：? 速查面板（GitHub 上下文分组/Slack 搜索框）/ 界面内联键位提示
   （pi keyHint/Zed 禁用变暗）/ 多段键 pending 指示（Zed 倒计时+which-key 自动
   浮现/opencode leader 面板）。
6. **作用域（when/context）是一等字段**：VS Code when 表达式/Zed context 树/
   pi 优先级规则明文/我方 inInput 硬编码——键位按焦点区域生效是所有成熟实现的
   共同假设，管理页以一列明示。

## 5. 改造方案（A~X 分级，打勾后实施）

> 每项实施前回对应参考仓核对实现级细节。验收链沿走查纪律：真改绑即时生效/真冲突

### A 域：动作空间扩展（命令注册表）

- **A1 动作集扩容**：8 动作 → 约 16 动作。新增（以 app.js 真实能力为准，实施前
