### 0.4 功能完整性的硬约束（写进每批 DoD）

1. **物理搬迁 + 行为冻结**：不删能力、不改行为、不改协议面、不改数据面。
2. **三道验收闸**：`npx vitest run` 全绿（基线 2,230）+ `npx tsc --noEmit` 干净 + `node tools/architecture-check.mjs` 无新增 error。

4. **外置 = 默认可用**：`ext-builtin` 三个包与 `plugins/tools-builtin` **默认随发行版内置**（体验与今天完全一致），
   只是"可裁剪/可替换"（对齐 pi 的 `replaceable: true` 与 pi-desktop 的"捆绑插件走公共通道"）。
5. **不引入新功能**：本轮重构不做 W2/W3/W4 等能力增强（那些是重构后的独立批次）。

## 1. 总体设计

### 1.1 四层与依赖铁律

```
  三 万物：plugins/（市场 + 用户插件）+ src/ext-builtin/（三个内置扩展包）+ plugins/tools-builtin/
                              ▲ 依赖
  二 派生原语（实现域）：src/{session,models,policy,context,sandbox,mcp,lsp,scheduler,attachments}
                              ▲ 依赖
  宿主层：src/runtime/（assembly + agent-process + registrations）｜ src/host/
                              ▲ 依赖（单向）
  ★ 0 + 一：src/core/  ← 纯内核：零跨域出边，只被依赖，不依赖任何域
```

**写进 `architecture-policy.json` 的规则（批 0 落地）**：
```
core    : managed:true,  requires:[], publicEntrypoints:["src/core/index.ts"]
runtime : managed:true,  requires:[core, 各域...]
其余域   : managed:true 逐步推进（存量域先 requires:[core,...现状] 再收紧）
```
> 与 `tools/architecture-check.mjs` 同源（zcode 语义）；核心差别是 **core 从 `managed:false` 升为硬约束**。

### 1.2 "类型下沉"清单（清零 type-only 跨域边的唯一手法）

type-only 边不能靠搬文件解决——必须把**被依赖的类型**下沉到 core，让原域**反向依赖 core**：

| 现类型 | 现在住哪 | 下沉到 | 反向改造 |
|---|---|---|---|
| `AttachmentRef` / `AttachmentStore` 接口 | `src/attachments/{types,store}.ts` | `core/contracts/attachments.ts` | attachments 域实现 core 接口 |
| `ChatTool` / `ChatMessage` / `ModelProvider` / `ModelIdentity` | `src/models/{provider,identity}.ts` | `core/contracts/models.ts` | models 域实现 core 的 `ModelProvider` |
| `ReadGateService` / 工具闸端口 | `src/policy/read-gate.ts` | `core/contracts/policy.ts` | policy 域实现该端口 |
| `SandboxBackend` / `ExecutionEnv` | `src/sandbox/backend.ts`、`kernel/tools/env.ts` | `core/contracts/sandbox.ts`（`ExecutionEnv` 已在 core） | sandbox 域实现 |
| `SessionStore` 接口 / `Projector` | `src/session/{store,project}.ts` | `core/contracts/session.ts` + `core/primitives/session/project.ts` | session 域实现/复用 |
| 插件 manifest/host 面 | `src/kernel/plugin-*.ts` | `core/contracts/plugins.ts` | `src/ext-builtin/plugin-runtime` 实现 |
| 记忆/渠道/调度端口（为 W3/W4/W16 铺路） | — | `core/contracts/{memory,channel,schedule}.ts`（新建） | 各域/插件实现 |

> 判据：**接口与 wire 形状住 core，实现住域**。做完这条，`loop.ts` 那 32 文件 / 9,721 行的传递闭包会塌成"core 内部"。
