# 内核重构总体方案：新建 `src/core` 纯内核（2026-10-10）

> 本文是**总体重构方案（施工蓝图）**，不是开工提示词——逐批实施提示词在看方案、你打勾后另写。
> 依据：`docs/20261010_内核架构对比与改造建议.md`（总报告，W1~W17）+ 三份分报告（路 A/B/C）。
> 本方案把 W1~W17 **落成具体目录设计 + 逐文件归属表 + 8 个实施批次**。
>
> 目标一句话：**新建 `src/core/` 装"重构后的内核"，它零跨域依赖；现有 `src/*` 域变成 core 的插件/宿主；
> 装配与进程编排搬出内核。** 由「道生万物」四层映射：`src/core` = 0 骨架 + 一 原语；
> `src/*` 各域 = 二 派生原语；`plugins/` + 市场 = 三 万物。
>
> **本会话只出方案，不改任何代码。**

## 0. 一页纸总览

| 项 | 现在 | 重构后 |
|---|---|---|
| 内核位置 | `src/kernel/`（82 非测试文件 / 21,978 行） | **`src/core/`（纯内核，目标 ~9,000 行）** |
| 内核依赖 | 依赖 8 个域（session 46 / models 42 / policy 32 / context 18 / attachments 12 / sandbox 11 / scheduler 4 / mcp 3 处 import） | **`core.requires = []`（零跨域出边，架构检查硬失败）** |
| 装配/进程 | `kernel/assembly.ts`(1,360) + `kernel/agent-process.ts`(2,033) 在核内 | **`src/runtime/`（宿主层，不在内核）** |
| 内置工具 | `kernel/tools/builtin/`（32 文件 5,254 行）编进内核 | **`plugins/tools-builtin/`（可裁剪工具包）** |
| 内核"重"的来源 | 装配中心 + 工具实现 + 内容（提示/技能/插件管理） | 只留 **0 骨架 + 一 原语**；其余全外置 |
| 依赖方向 | 双向（kernel→session 且 session→kernel） | **单向：`core ← src/*域 ← src/runtime ← src/host`** |
| 强制手段 | `managed:false`（违规只 warn） | **`core` 域 `managed:true` + `requires:[]` + `publicEntrypoints`，违规硬失败** |

**关键实测事实（方案的事实基础）**：
- kernel 里 **46/82 个文件零跨域出边**（纯）；35 个有出边。
- 跨域 import 共 156 条：**44 条 type-only、112 条 runtime**。runtime 依赖**集中在 4 个文件**：
  `assembly.ts`、`agent-process.ts`、`agent-child.ts`、`agent-child-config.ts`（这 4 个就是要搬出内核的"装配/进程"）。
- 其余 runtime 跨域依赖几乎全是**内置工具**对 `sandbox/policy` 的依赖（`bash/read/write/edit/pwsh/...`）——随工具一起外置即可。
- 内核自带的 `events.ts`/`queue.ts` 只 **type-only** 依赖 `attachments/types.ts`（`AttachmentRef`），
  `tools/registry.ts` 只 **type-only** 依赖 `models/provider.ts`（`ChatTool`）——**两条 type 边用"类型下沉"即可清零**。

**重构后内核规模预估**：`src/core/` ≈ **9,000 行**（对照 pi 内核 2,519 行 / pi-desktop 语义核 2,459 行）。
不是"最小"（我方循环语义更厚：取消/看门狗/流恢复/预算都在核内），但**语义面**已收敛到"0 + 一"。

## 1. 总体架构设计

### 1.1 四层与依赖方向（唯一铁律）

```
                         ┌─────────────────────────────────────┐
                         │  三 万物：plugins/ + 市场 + 用户插件   │
                         └─────────────────────────────────────┘
                                        ▲ 依赖
        ┌───────────────────────────────────────────────────────┐
        │  二 派生原语（插件/宿主）：src/{session,models,policy,   │
        │     context,sandbox,mcp,lsp,scheduler,attachments,     │
        │     prompts,subagent,...} + plugins/tools-builtin/     │
        └───────────────────────────────────────────────────────┘
                                        ▲ 依赖（单向）
        ┌───────────────────────────────────────────────────────┐
        │  宿主/装配层：src/runtime/（assembly + agent-process）   │
        │              src/host/（WS/网关/渠道/调度服务）          │
        └───────────────────────────────────────────────────────┘
                                        ▲ 依赖（单向）
        ┌───────────────────────────────────────────────────────┐
        │  ★ 0 + 一：src/core/  ← 纯内核，零跨域出边，只被依赖     │
        │     0 骨架：事件/协议/链/队列/预算/生命周期/日志         │
        │     一 原语：agent 循环 + 会话投影 + 工具契约 + 进程模型  │
        └───────────────────────────────────────────────────────┘
```

**依赖铁律（写进 `architecture-policy.json`，`core` 域 `managed:true`）**：
```
core 允许依赖：core/* 内部 + node 内置
core 禁止依赖：src 下任何其它域（session/models/policy/context/sandbox/…）
其它域允许依赖：core
runtime/host 允许依赖：core + 各域
```
> 与现有 `tools/architecture-check.mjs` 同源（zcode 语义）——只是把 `core` 从 `managed:false` 升为硬约束。

### 1.2 "类型下沉"清单（清零 type-only 跨域边的唯一手法）

type-only 边不能靠"搬文件"解决，必须**把被依赖的类型定义下沉到 core，让原域反向依赖 core**：

| 现类型 | 现在住哪 | 下沉到 | 反向改造 |
|---|---|---|---|
| `AttachmentRef` / `AttachmentStore` 接口 | `src/attachments/types.ts`、`store.ts` | `src/core/contracts/attachments.ts` | attachments 域实现 `core` 的接口 |
| `ChatTool` / `ChatMessage` / `ModelProvider` 接口 / `ModelIdentity` | `src/models/provider.ts`、`identity.ts` | `src/core/contracts/models.ts` | models 域实现 `core` 的 `ModelProvider` |
| `ReadGateService` | `src/policy/read-gate.ts` | `src/core/contracts/policy.ts` | policy 域实现该端口 |
| `SandboxBackend` / `ExecutionEnv` | `src/sandbox/backend.ts`、`kernel/tools/env.ts` | `src/core/contracts/sandbox.ts`（`ExecutionEnv` 已在 core） | sandbox 域实现 |
| `SessionStore` 接口 / `Projector` / `buildChatMessages` / `effectiveEvents` / `computeCacheAnchor` / `trimToolResultMessages` | `src/session/*`、`src/context/*` | `src/core/contracts/session.ts` + `src/core/loop/*` | session/context 域实现或复用 core |

> 判据：**接口与 wire 形状住 core，实现住域**。这条做完，`loop.ts` 的 32 文件闭包（9,721 行）会塌成"core 内部"。

### 1.3 三层内核目录（`src/core/` 内部）

`src/core/` 内部再分三层（便于"0 与一"可分辨、可度量）：

| 层 | 目录 | 内容 | 行数预估 |
|---|---|---|---|
| **0 骨架** | `src/core/{events,protocol,chain,hooks,queue,budget,deadline,timeout,admission,invariants,run-state,rw-lock,goal,logger,raw-chunk-log}.ts` | 公共语言与配件，零域依赖 | ~4,100 |
| **一 原语** | `src/core/loop/*`（循环+护栏）、`src/core/tools/*`（契约+注册表+调度）、`src/core/process/*`（进程模型）、`src/core/contracts/*`（端口类型） | 循环/会话投影/工具契约/进程 | ~4,000 |
| **内核内的"可外置候选"** | `src/core/plugins/*`（manifest/loader/contributions）、`src/core/prompts/*`、`src/core/subagent/*` | 先搬进 core 保行为，P2 再外置成插件（见 §5 批次 7） | ~2,400 |
