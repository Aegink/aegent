## 6. 附录：zcode 预研报告（本会话已完成，下会话直接引用）

> 来源：本会话派发的 zcode 内核对照 agent（29628c9），完整报告见下。
> 结论一句话：**zcode 把"指挥别的会话"做成模型工具（SendMessage/ReadContext/TaskOutput）+ 子 runtime 独立会话；我方把协作做成了服务库 + UI op，能力在但没接到模型手上——补齐是"加工具 + 接回投"的小-中成本，不必重写内核。**

### 0. 关键纠正（坐标）
zcode 内核是两层，`packages/services/src/` 不是循环本体：
- **执行层**（循环/工具/子代理）：`oss/zcode/apps/zcode-cli/packages/core/src/`
- **管控层**（起 agent 进程/会话编排/机器人/索引 DB）：`oss/zcode/packages/services/src/`
- services 通过 `ZCodeAgentProcessManager`（`packages/services/src/zcode-agent/zcodeAgentProcessManager.ts:538`，spawn `:1019`）把 CLI agent 当子进程管；循环在 core。

### 1. 模块地图（锚点节选）
| 模块 | 职责 | 锚点 |
|---|---|---|
| services/zcode-agent | 派生/监管 agent 子进程、协议客户端、task 适配 | `zcodeAgentProcessManager.ts:538`；`zcodeAgentService.ts:1057`(create)、`:3423`(createSession)、`:4430`(sendPrompt) |
| services/zcode-session | 桌面侧会话门面（CRUD/subscribe/draft） | `zcode-session/zcodeSession.ts:31`(CreateParams，含 parentSessionId:35) |
| services/session | task 索引 SQLite + cron/off-peak + 邮箱契约 | `session/zcodeTaskService.ts:1`；`tasksDatabase/migrations.ts:45`；`sessionMailbox.ts:1` |
| services/subagents | 子代理 profile 定义（markdown）存储，非运行体 | `subagentsService.ts:543` |
| services/bots | IM 渠道（飞书/TG/微信/webhook）建真实 task | `botsService.ts:679`、`:5404`(handleInbound)、`:4868`(createTask) |
| core/runtime | AgentRuntime + 全部 turn 方法 | `runtime/methods/turn.ts:70`；`turn-loop.ts:47`；`turn-model-step.ts:88`；`turn-tools.ts:43` |
| core/tool | 注册表/执行器/调度/审批 | `tool/registry.ts:29`；`executor/impl.ts:16`、`call-runner.ts:65`；`scheduler.ts:29`；`executor/approval-gate.ts:36`、`permission-flow.ts:41`；handlers 40+ 于 `tool/handlers/index.ts:69` |

| core/dynamic-workflow-runtime | 工作流脚本子进程 harness | `dynamic-workflow-runtime/src/harness.ts:77`；`bootstrap/src/app/workflow-facade.ts:87` |

### 2. 循环与工具执行
一轮：`executeTurn`(`turn.ts:70`)→命令队列→`runRegularTurnLoop`(`turn-loop.ts:47` while(true))：每步 drain 运行时命令、micro/auto compact、`initializeMcp`、取工具，再 `runModelBackedTurnStep`(`turn-model-step.ts:88`)（流式 + streaming-tool-coordinator 边流边收 tool_call），随后 `executeToolCallsForModelStep`(`turn-tools.ts:43`)：`ToolScheduler` 拓扑排序+并行组（`scheduler.ts:29`，maxConcurrency 10，只读并发/副作用串行）→`ToolExecutorImpl`(`impl.ts:16`)→`executeToolCall`(`call-runner.ts:65`)→`resolveToolPermission`(`permission-flow.ts:41`，hook 链与 broker 竞速取先到者)+`resolveToolApproval`(`approval-gate.ts:36`)→handler。
工具形态：`ToolEntry = { metadata(name/readOnly/destructive/concurrentSafe/needsApproval/sideEffectScope/riskLevel/maxOutputBytes/timeoutMs) + handler + inputSchema(JSON Schema) + runtimeInputSchema(zod) + permission + resultBudget + timeout + cancellation + trace }`，`registry.toContracts()`(`registry.ts:89`) 投影给 provider，支持 alias（Task→Agent）。
**差异**：zcode 是"薄 handler + 重声明式元数据 + 统一执行管线"；我方是"每工具一个大实现 + ToolDef + chain 审批"——权限/预算/超时/取消/追踪未结构化声明。

### 3. 会话模型与编排（跨会话机制逐个）
会话创建：只有 UI/RPC/宿主路径（`session-mgmt.ts:33`→`zcodeAgentService.createSession:3423`）；**模型无任何创建顶层会话的工具**。会话类型闭集 `SESSION_TASK_TYPES`（`session-store.port.ts:24`）= interactive/fork/selection_side_chat/workflow_parent/**workflow_child**/**subagent_child**/nested_workflow_child。
1. **子代理（模型可发起）**：`Agent`/`Task` 工具（`tool/handlers/agent.ts:223`）→子 runtime 独立会话 `subagent_<agentId>`（`runtime/methods/subagent.ts:805-806`），持久化/可后台/可续跑；事件 SubagentSpawned/Message/Stopped（`session.events.ts:167-169`）。
2. **SendMessage 工具**（模型→其他 agent）：`handlers/send-message.ts:48`→`subagentPort.sendMessage`(`runner.ts:568`)：运行中投递/入队（`:936`），终态后台重启续跑（`:950`）。
3. **TaskOutput/TaskStop**：轮询/停后台 agent。
4. **子→父回话**：`RespondToCoordinator`（`respond-to-coordinator.ts:30`）、escalate、submit_result。
5. **ReadSessionContext 工具**：按 sessionId 读任意会话持久化原文（`read-session-context.ts:37`）。
6. **CreateWorkflow**：模型写 TS 脚本 spawn 子代理 actor（子会话 `workflow_<activityId>`，`workflow-facade.ts:87`）。
7. **会话间邮箱**：信封契约 `session-mailbox.port.ts:1`；文件适配器 `adapters/src/mailbox/index.ts:15`（drainUnread）；消费=内建 hook 在 UserPromptSubmit/PostToolUse/Stop drain（`core/src/hooks/session-mailbox.ts:11-30`），注入 `<session-message from_session=...>` 并 steer 进当前轮；路由=`workspace_session_message_send_requested`（`shared/zcode-task-types.ts:192`）→desktop host 转发（`desktop/src/host/index.ts:1180`、`:1202`）→main TaskRealtimeBus（`taskRealtimeBus.ts:920`）→目标 host `deliverSessionMessage`（`host/index.ts:2470`）。**缺口：目标侧是 stub（`zcodeTaskServiceAdapter.ts:1942` unsupported）、发射侧在 OSS 快照缺失——管道在，端到端不可用。**
8. **bots**：IM 入站→建真实 task+发 prompt（`botsService.ts:5404`、`:4868`）。
9. **automation/cron**：定时向目标 task 发 prompt（`automationService.ts:141`、`:243`）。
结论：zcode 中"一个会话指挥多个真实会话"的模型侧原语全部是**子 runtime**（subagent/workflow actor，各有独立持久 sessionId）；面向**平级顶层会话**的创建/指挥只有 UI/bot/host 权限，模型不可达。

### 4. 与我方逐面对照（摘要）
| 面 | zcode | 我方 |
|---|---|---|
