## 0. 结论一句话

我方**引擎侧已有被埋没的日志基座**（kernel/logger.ts：四级+按日文件+双层脱敏+JSONL 行，7 处消费）但 **host 进程没接入、UI 零露出**——设置页只有一个 rawLogDir 输入框。参考生态（14 仓）里 pideck 有唯一完整的页内日志查看器、zcode 与我方"按天分文件+保留清理"目标最同构、pi-desktop 有最完备的分类体系。建议把该分节升级为**「日志中心」**：统一管道（host/agent/ui/raw 四通道按日文件+分类命名）+ 页内查看器（级别/分类/搜索/分页）+ 诊断包导出，分节语义从"存日志的目录"扩为"排障基础设施"。用户点名的「24h 单独一文件」有 pideck/zcode 两家先例且与现有基座天然对齐——**采纳，评估详见 §4**。

## 2. 我方现状（本地源码深读）

### 2.1 已有基座（比预想好——但被埋没）

- **kernel/logger.ts（131 行，T-6-05/D9 产物）**：`createLogger()` 四级（debug/info/warn/error）、**按日一文件** `aegent-YYYYMMDD.log`（缺省 "logs" 相对 cwd）、行格式 JSONL `{ts, level, msg, data?}`、**双层脱敏**（密钥正则 sk-[A-Za-z0-9-]{19,} → [REDACTED:api-key] 恒开；用户原文约定字段 userContent → [REDACTED:user-content] 缺省开）、写失败降级告警一次不带崩。消费方 7 处：models/health、kernel/agent-child、plugin-loader、assembly、loop、subagent、raw-chunk-log。
- **kernel/raw-chunk-log.ts（64 行，E14）**：模型原始流分片 JSONL，**已按日** `raw-YYYYMMDD.jsonl`+redactSecrets；目录来自 `--raw-log-dir`（settings.logging.rawLogDir——**UI 唯一露出的日志功能**）。
- **diagnostics/doctor.ts**：运行时诊断报告（环境/配置/存储三组检查行+--json 导出）——日志域的"体检"面已存在。
- **portable host.log**：tauri 壳（src-tauri/lib.rs:27-37）把 host stdout/stderr 追加落 `logs/host.log`——**单文件无轮转无分级**。

### 2.2 断点（"简陋"的实相）

1. **host 进程没接 createLogger**：host/gateway 全是散布 `console.error` → stderr → 只有 portable 壳兜底成无轮转 host.log；dev 模式下 host 日志直接丢失。
2. **UI 侧零捕获**：无 window.onerror/unhandledrejection——渲染层崩溃丢诊断信息。
3. **UI 零露出**：设置页只有 rawLogDir 一个输入框；没有任何日志查看/过滤/导出面。
4. **分类缺失**：行 schema 无 category；文件名无通道区分（kernel 的 logs/ 相对 cwd，分片另走 rawLogDir，host.log 又是一处——三处互不相认）。

## 4. 「24h 单独一文件」与「分类命名」评估（用户点名"好好评估"）

### 4.1 按天分文件（24h 一文件）——采纳，理由与代价

**支持面**：
1. **用户诉求与现有基座天然对齐**：kernel/logger.ts 已按日 `aegent-YYYYMMDD.log`、raw-chunk-log 已按日 `raw-YYYYMMDD.jsonl`——不是新造，是把既有约定铺开到全部通道。
2. **参考先例充分**：pideck `app-YYYY-MM-DD.log`（保留 14 份）+zcode `YYYY-MM-DD.log`（保留 14 天）——两家桌面工作台同构先例，清理=整文件删除（比大小轮转的截断归档简单一个量级）。
3. **排查语义直观**："昨晚出的问题"→直接打开昨天的文件；按天边界与人类排查口径一致。
4. **保留策略零歧义**：按天文件+保留 N 天=直接删旧文件；不需要轮转重命名链。

**代价与对策**：
- 单日大流量（debug 全开+长会话）文件可能大 → **双保险**：debug 级默认只进"当前会话诊断"不常驻（见 4.3 默认档），info 常驻单日体量可控；再加单文件 64MB 软上限告警（不截断——排查完整性优先）。
- 跨午夜长会话日志分属两文件 → 接受（每行自带 ts 可重排；pideck/zcode 同样如此）。

### 4.2 分类命名体系——四通道×category（pi-desktop 的简化落地）

pi-desktop 十分类目录树对我方体量过重；pideck 单层 scope 略粗。**中庸方案**：
- **通道（channel）=文件级分类**：`<dataDir>/logs/` 下四类文件——`host-YYYYMMDD.log`（host/gateway 面）、`agent-YYYYMMDD.log`（agent 子进程面，含 stderr 归管）、`ui-YYYYMMDD.log`（渲染层上报）、`raw-YYYYMMDD.jsonl`（模型原始分片——现状沿用）。文件名即通道，一眼定位。
- **category=行级分类**：行 schema 从 `{ts, level, msg, data?}` 扩展为 `{ts, level, channel, category, msg, data?}`——category 由调用方给（规范化闭集建议：transfer/mcp/provider/policy/session/plugin/gateway/speech/prompt/project，未知值允许但 lint 提示——qwen tag 模式）。
- **event 稳定机器名**：关键行补 `event` 字段（pi-desktop 锚——如 `settings.import`、`lease.denied`），命名规范=点分小写动词短语；message 保持人话。
- **host 收编**：host 现有散布 console.error 全部改为 logger 调用（category 归位）；tauri 壳的 host.log 重定向保留为兜底（壳无法感知新管道时仍有 stderr 可看）。
- **agent 侧归管**：agent 子进程 stderr 的 `[aegent]` 行由 host 转写进 agent-*.log（pi-desktop logger.child 锚）；子进程自身 createLogger 落点统一改 `<dataDir>/logs/`（现状相对 cwd 散落）。

### 4.3 默认档与开关——常驻 info（与 CLI 大厂反着选，理由）

CLI 三强默认关（无常驻进程、隐私面小）；我方是**本地常驻工作台**且用户明示"日志非常重要，是后续任何错误的排查点"——**默认 info 常驻**（pideck/zcode 同款），debug 可开（设置热更，cc-switch set_max_level 锚）、redact 恒开不可关（密钥）/userContent 可关（现状开关沿用）。日志目录缺省 `<dataDir>/logs/`（~/.aegent/logs），settings.logging.logDir 可改写（rawLogDir 收编进该体系，旧键兼容读）。

## 5. 改造方案（A~F 分级，打勾后实施）

分节升级为**「日志中心」**，五卡组：日志管道 / 查看器 / 分片日志 / 诊断包 / 设置。

### A 域：日志管道统一（采集端——"分类且详细地记"）

- **A1 host 接入 createLogger**：host/gateway 面散布 console.error 全部收编为 logger 调用（category 归位：transfer/mcp/provider/gateway/...）；落 `<dataDir>/logs/host-YYYYMMDD.log`。
- **A2 行 schema 扩展**：LogEntry 加 `channel/category`（可选字段——旧行兼容）；createLogger 加 `channel/category` 构造参；文件名改 `<channel>-YYYYMMDD.log`（kernel 缺省通道名 `agent`）。
- **A3 UI 错误捕获**：window.onerror+unhandledrejection → 新 op `log-report`（批量上送节流）→ host 落 `ui-YYYYMMDD.log`（zcode renderer 桥接+cc-switch 三层捕获锚）；React 渲染错误边界提示"已写入日志"。
- **A4 agent stderr 归管**：host 对 agent 子进程 stderr 行按 `[aegent]`/级别字样转写进 `agent-*.log`（pi-desktop categoryForChild 锚）；子进程 createLogger 落点统一到同一 logs 目录。

### B 域：按日文件与保留（"默认 24h 一文件"）

- **B1** 全通道按日文件 `<channel>-YYYYMMDD.log`（raw 沿用 .jsonl）。
- **B2 保留期**：settings.logging.retentionDays（默认 **14**，0=永久）——写入路径顺带清理过期文件（zcode logRetention 锚，绝不阻塞调用方）。
- **B3 单文件 64MB 软上限告警**（不截断，排查完整性优先——写入时 logger.warn 一次）。
- **B4 日志目录**：缺省 `<dataDir>/logs/`；settings.logging.logDir 可改；rawLogDir 旧键兼容迁移。

### C 域：页内日志查看器（"排查点"主战场——pideck 形态）

### 验收清单草案（打勾后按此实测）
