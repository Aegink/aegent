# AI 自动驱动浏览器：承载选型调研（2026-10-05）

> 调研问题：agent 要能操作网页（browser_navigate/click/type/screenshot 工具族），承载选哪个——
> **方案 A**：壳 child webview 的 CDP 控制通道（`src-tauri/src/browser.rs` 已有面板 command 面）；
> **方案 B**：独立 Playwright 进程（Node 侧 playwright-core）。
>
> 证据标注体系：**【真机实测】**=本机走查证据（scratch/notes 存档）；**【官方】**=官方文档/docs.rs/npm registry；**【仓内实读】**=参考仓代码结论；**【推断】**=分析判断。

---

## 1. 结论先行

**推荐"A 扩展"分期路线**：近期做 **方案 A 扩展**（browser.rs 面板 webview 配专属数据目录 + CDP 端口暴露 + 端口发现；内核侧把 T-P2-407 已写好的 `src/scheduler/browser.ts` CDP 工具族接线）——agent 驱动的就是**用户看得见的浏览器面板**（zcode/pi-desktop 的同款关系），零新依赖；中期需要 locator 语义（可靠 click/type/等待）时做 **B 融合**（playwright-core `connectOverCDP` 连同一个面板端口），13.4MB 依赖在需要时再付。**不做** B 独立隐窗与 chromium 下载版 playwright。

## 2. aegent 现状资产盘点（先看清手里有什么）

调研发现项目已有**三块直接相关的资产**，选型不是从零开始：

| 资产 | 位置 | 状态 | 说明 |
| --- | --- | --- | --- |
| 浏览器面板壳承载 | `src-tauri/src/browser.rs` | 已落地（T-P3-169 终版） | 主窗内嵌 child webview（WebView2），command 面：`browser_create/show/hide/navigate/destroy/eval`；前端 `ui/pane-browser.js` |
| CDP 直连工具族 | `src/scheduler/browser.ts` | 已落地、未接线（T-P2-407） | CDP over ws 直连（`CdpConnection` + `cdpWsUrlOf`），三工具 `browser_navigate/screenshot/extract`，含 D3 域白名单、每导航显式审批（fail-closed）、M7 deadline（BROWSER_DEADLINE）、NOTICE 风险标注 |
| 面板前端 | `ui/pane-browser.js` | 已落地 | ResizeObserver 对齐 bounds、Tab 保活（browser_hide 不销毁）、前进/后退/刷新走 `browser_eval` |

关键事实：

- `browser.rs` 的 `browser_eval` 走 `webview.eval(&js)`（tauri → wry → WebView2 `ExecuteScript`），**fire-and-forget，无返回值**（`Result<(), String>`；`lib.rs` 的 `spawn_update_check` 也是同款单向 eval 调 UI）。JS 结果回不来，是方案 A 单靠 eval 撑不起工具面的根因。
- `scheduler/browser.ts` 头注锚点即 qwen·packages/browser-use 的"工具族 + 独立网络策略 + 风险标注"行为，**明确不引 playwright 依赖**（"我方 CDP 协议直连最小面"）。
- 工具注册入口 `src/kernel/tools/builtin/index.ts` 的 `BUILTIN_TOOL_NAMES` 里**还没有 browser_* 主对话面**（browser 三件目前只在 scheduler 域、仅测试 import；装配面空缺）。
- 【真机实测】T-P3-174 批次 5 记档（`notes/20261005_t-p3-174-batch5-shell.md` 第 6 条）：**"browser_create 子 webview 附着后 CDP target 重建断连（自动化面限制）"**——CDP 连接不能假设 target 恒定，须重连逻辑。

## 3. 参考仓摸底

### 3.1 总表

| 仓库 | 有无 agent 浏览器自动化 | 承载 | agent 驱动的关系 |
| --- | --- | --- | --- |
| zcode | 有（两套） | Electron `<webview>` guest + `webContents.debugger`（CDP 直通）+ playwright 注入脚本语义 | **驱动同一个用户可见浏览器面板**；CLI 经 broker socket 调桌面宿主 |
| opencode | 无 | 仅 `open` 打 URL | — |
| codex | OSS 核心无引擎 | 只有配置/审批策略管道（host app 实现） | 策略面值得抄：origin policy 含 `full_cdp_access` 闸 |
| pi（CLI） | 无 | `browser-smoke` 是"包导出可跑在浏览器环境"的冒烟，非自动化 | — |
| pi-desktop | 有（ADR 0170） | 宿主持有 `WebContentsView` guest + `webContents.debugger`；raw CDP 白名单 deny-by-default | **同一可见 guest**；navigate/snapshot/screenshot/console 进 Plan 面，click/fill/evaluate/cdp 仅 Agent |
| qwen-code | 有（最重） | playwright-core + 自定义 CDP transport（Chrome 扩展 Native Messaging） | 驱动**用户现有 Chrome**（带登录态），不是自家面板 |
| hermes-agent | 有（云 provider） | 云浏览器（Browserbase/Browser Use）返回 CDP URL；桌面端 Electron 内嵌浏览器窗 | 云 session 的 CDP URL 直连 |
| deepseek-harness | 无 agent 面 | Electron 侧栏 webview guest（严格 partition 隔离） | 用户面 |

### 3.2 zcode（最完整的同构参照）

- 承载：桌面端 `<webview>` guest，`browserGuestManager` wire 到 `webContents` + `webContents.debugger`（Electron 内嵌 CDP 直通，**不开端口、无鉴权面**）。`packages/desktop/src/main/browserView/browserGuestManager.ts`（attach/rebind 串行屏障、CDP 消息监听随 guest 换代注销）。
- 命令执行器：`browserCommandExecutor.ts`——核心子集 navigate/getState/screenshot/snapshot/click/type/press/scroll，其余 fill/waitFor 返回 `capability_unsupported`；`browserCommandTypes.ts` 的 `ControlledView` 抽象（webContents + cdp 双面）值得借鉴。
- locator 语义：**不引 playwright 驱动库**——`browserPlaywrightLocatorExecutor.ts` 把 playwright 的 injected script 源码（从 playwright-core 包里读出，`playwrightInjectedScriptSource.ts`）序列化后注入页面隔离 world 执行，用 playwright 的选择器引擎但不跑 playwright 进程。playwright-core 在 desktop 是普通依赖（`packages/desktop/package.json` 第 54 行），**只为读这段注入源**。
- 截图：优先从宿主 compositor surface 直读（`captureViewportScreenshot`），避开 Windows 下 CDP 对小 surface 的平铺问题（`browserCommandTypes.ts` 注释）。
- CLI/插件关系：`browser-use-plugin`（MCP）→ `node-repl-host/browser-bridge.ts` → 命名管道 broker（`bootstrap/src/zcode-protocol/browser-control-broker.ts`）→ 桌面宿主执行。**agent 与用户看的是同一个面板**（tab residency、tab 恢复都有）。
- 结论：zcode 证明"驱动可见面板 + CDP 直通 + 注入脚本补 locator 语义"在生产可行，且 tab 换代/target 重建的恢复逻辑是必要品（与 aegent 【真机实测】的断连记档同构）。

### 3.3 opencode / codex

- opencode：核心无自动化。`packages/opencode/src/mcp/browser.ts` 只是 `open` 子进程开 URL；`@playwright/test` 仅 e2e devDep（`packages/app/e2e/`）。
- codex：`codex-rs` 核心无浏览器引擎，只有策略管道——`codex-rs/config/src/browser_use.rs`（origin policy：access/downloads/uploads/**full_cdp_access** 四闸）、`in_app_browser_requirements.rs`（明确注释"managed requirements for the interactive in-app browser, not agent Browser Use"）。策略形状（按 origin 分域授权 CDP/下载/上传）对未来做权限面有直接参考价值。

### 3.4 pi / pi-desktop

- pi CLI：无自动化。`scripts/browser-smoke-entry.ts` 是防"Node-only import 混进浏览器面导出"的 bundle 冒烟，与驱动浏览器无关。
- pi-desktop `docs/adr/0170-work-panel-browser-as-bundled-plugin.md`（Accepted，2026-09-06）——与 aegent 形态最贴近的裁决：
  1. 浏览器 = 捆绑插件，guest `WebContentsView`（`persist:work-browser`）+ debugger **宿主持有**，插件只做 chrome；
  2. agent 工具 `Browser` 与用户可见面板**同一个 guest**（会话位置记忆、后台会话不抢可见 guest）；
  3. **raw CDP 白名单、deny-by-default**（cookie/storage/target/网络拦截拒掉，不暴露 DevTools ws）；
  4. bounds 钳制在调用方插件视图内（防 guest 盖住聊天区）。
- 结论：pi-desktop 从治理角度补全了 zcode 的做法——**同一可见 guest + CDP 白名单收缩**，是方案 A 安全面的直接蓝本。

### 3.5 qwen-code（方案 B 的完整参照）

- `docs/design/browser-use.md`：`playwright-core@1.62.1` 走 `chromium.connectOverCDP(transport)` 自定义 transport（`QwenPlaywrightTransport` → `ChromeExtensionTransport` → Native Host → Chrome 扩展 `chrome.debugger`）驱动**用户现有 Chrome**（tabs/profile/登录态）。SDK 跑在 Node REPL 常驻内核里，skill 捆绑 runtime（含钉版 playwright）。
- 复杂度最高的一档：扩展 + Native Host 安装器 + profile 握手 + 会话所有权——aegent V1 不需要驱用户日常 Chrome（有自己的面板），这套基建可整体不取；但**"playwright-core 接受自定义 CDP transport"这个能力**正是 B 融合路线（连自家面板端口）的技术依据。
- `packages/browser-use/src/` 分层（runtime 校验/预算、sdk、playwright adapter、bridge）可作为中期 B 融合的结构参照。

### 3.6 hermes-agent / deepseek-harness（略）

- hermes-agent：`agent/browser_provider.py`（云 provider ABC：create/close/emergency_cleanup，返回 `cdp_url`）+ `agent/browser_registry.py`；桌面端 Electron 弹出式浏览器窗（`apps/desktop/electron/browser-windows.ts`）。云 CDP URL 直连模式，对本项目（本地优先、便携、零云）只有接口形状参考。
- deepseek-harness：`apps/desktop/src/browser-guests.ts`——侧栏 guest 的 partition 隔离策略（workspace → `dsh-sidebar-browser-<uuid>` partition），无 agent 驱动面。

## 4. 方案 A 深挖：壳 child webview 的 CDP 控制通道

### 4.1 现有 eval 面能不能撑 click/type/screenshot

- **eval（现状）**：`webview.eval(&js)` 无返回值（§2）。可单向注入 JS 做 click（`el.click()`）/type（赋值 + dispatchEvent），但 agent 拿不到执行结果、报不了错、等不了条件——只能算"半根手指"。
- **CDP page target（补上就齐）**：【真机实测】T-P3-164/167 走查已在本机验证 WebView2 开 `--remote-debugging-port=9223` 后，`ws://127.0.0.1:9223/devtools/page/<target>` 直连、`Runtime.evaluate {returnByValue:true}` 带值往返（`scratch/_tmp_p164/cdp-drive.cjs`）；`cdp-pages.json`/`cdp4.json` 显示面板里 bing.com 的 page target 与主 UI target 同列 `/json/list`。也就是说 **page target 的 CDP 域全可用**：`Page.navigate`/`Page.captureScreenshot`/`Runtime.evaluate`/`Input.dispatchMouseEvent`/`Input.insertText`/`Emulation` 等——`scheduler/browser.ts` 的 `CdpConnection` 无需改协议即可复用，缺的只是 click/type 两个动作函数（`Input` 域或 evaluate 注入均可）。
- **screenshot 注意点**：zcode 实测 Windows 下 CDP 对小 surface 截图会平铺（§3.2），其解法是宿主 compositor 直读——aegent 无此能力，但面板创建时保持非零尺寸（现 `browser_create` 藏 400x300 于视口外，不置 0）基本可规避；截屏前可先 `Emulation.setVisibleSize` 或对可见面板截（【推断】，落地时真机复验）。

### 4.2 CDP 端口怎么暴露（WebView2）

- 通道一：进程级环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223`（WebView2 官方支持的注入面；走查即此法）【官方】。
- 通道二：per-webview `WebviewBuilder::additional_browser_args(...)`——tauri 2.12.0 确认存在（Windows 专属）。两条官方告警【官方】：①**不同 browser args 的 webview 必须配不同 data directory**；②默认 wry 已传 `--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection`，自定义后要自己补。
- 端口发现：`--remote-debugging-port=0`（随机端口）时 Chromium 把实际端口写进 user data 目录的 `DevToolsActivePort` 文件——给面板 webview 配专属 `data_directory`（tauri 2.12 `WebviewBuilder::data_directory` 确认支持 Windows【官方】）后即可从该目录读端口。此法在本项目未实测，落地第一件事就是真机复验【推断】。
- **安全要点（当前形态的关键缺口）**：现 `browser.rs` 未配 data_directory，面板与主 UI 共享同一 WebView2 环境/browser process——【真机实测】cdp-pages.json 里 `http://tauri.localhost/`（主 UI）与面板 target 同端口暴露。开端口即把主 UI（含会话流、凭据内存面）暴露给本机任意进程（CDP 端口无鉴权）。**必须**给面板 webview 配专属 data directory：既满足 tauri 的 args/data 配对要求，又让端口只暴露面板 target（顺带兑现 browser.rs 头注"数据目录独立"的设计意图）。

### 4.3 依赖体积与便携性

- **零新依赖**：CDP 客户端复用 `scheduler/browser.ts`（ws 已是依赖），端口发现/注入在 Rust 侧 std 内完成。WebView2 Runtime 是 Evergreen 系统组件（Win10/11 随系统分发，非便携包内字节）【官方】。便携总包 187.6MB 纹丝不动。

### 4.4 局限清单

| 局限 | 说明 | 缓解 |
| --- | --- | --- |
| 无 headless | WebView2 无 headless 形态【官方】；隐藏 webview 的 `background_throttling` tauri 文档标 Windows 不支持（隐藏时定时器可能被节流，影响 wait 类语义）【官方】 | 面板本就是可见窗场景；后台 tab 用 `Page.captureScreenshot` 强制渲染（【推断】，复验） |
| target 重建断连 | 子 webview 附着后 CDP target 重建（【真机实测】batch 5 记档）；多 tab 增删都动 `/json/list` | 按 label→url 映射每次操作前查 `/json/list` 重取 target；断线重连（zcode browserGuestManager 同款问题、可抄其 rebind 屏障思路） |
| 端口无鉴权 | 本机任意进程可连该端口（CDP 既有性质）【官方】 | 专属 data directory 隔离暴露面 + 随机端口（DevToolsActivePort）+ 用完 `browser_destroy` 时收口；中期可学 pi-desktop 在工具面再做 CDP 方法白名单 |
| 文件下载 | CDP Browser 域在 WebView2 受限【推断】；但 tauri `WebviewBuilder::on_download` 存在（`DownloadEvent::Requested/Finished`，可重定向落盘路径）【官方】——Rust 层可兜 | browser.rs 加 on_download 挂下载目录 |
| 多窗管理 | 每 tab 一个 page target，`/json/list` 天然列出 | 可做，非障碍 |
| 壳连坐 | 面板 webview 在壳进程内：壳崩面板亡（但 agent 内核在独立 node host 进程，host 不受影响） | 可接受——面板本来就是壳的一部分 |

## 5. 方案 B 深挖：独立 Playwright 进程

### 5.1 体积与浏览器二进制来源

- **playwright-core**：npm 1.63.0，unpacked **13.45MB / 114 files，零运行时依赖**【官方 registry】。便携包 187.6MB → ~201MB（+7%）。注意 `playwright` 完整包（~5MB）同样不含浏览器二进制，二进制一律 `npx playwright install` 单独下载（chromium ~150MB 级）——**便携版绝不走下载路线**。
- **浏览器从哪来**：`chromium.launch({ channel: "msedge" | "chrome" })` 用**系统已装的 Edge/Chrome**（Windows 必有 Edge），零下载零字节【官方】；或 `chromium.connectOverCDP(port)` 连既有浏览器（系统浏览器调试端口，或**方案 A 开的面板端口**——融合路线）。
- 二进制来源与 aegent 便携纪律相容（qwen 选扩展直连用户 Chrome、zcode 用 Electron 自带 Chromium，均零下载；下载版无人取）。

### 5.2 启动开销与接线形状

- 开销：spawn node 子进程（~100ms）+ require playwright-core（~100-200ms）+ 冷启 msedge channel（~0.5-1s）【推断】。**常驻 worker 摊销**后一次性付出。
- 接线形状 = **spawn 常驻子进程 + stdio JSON 行协议**，仓内已有完整同构先例：`src/host/local-stt.ts` + `local-stt-worker.ts`（T-P3-174 G1）——spawn/readiness 行/串行请求队列/空闲回收（30s 无请求杀 worker）/崩溃摘除，协议 `{"id":...}` 双向 JSON 行。新加 `browser-driver.cjs`（`tools/build-host-bundle.mjs` 的 bundle 清单加一行，同 host.cjs/agent-child.cjs 布局），host 侧 lifecycle 照抄 local-stt。隔离性已验证过：worker 崩溃不带走 host。
- 工具面：playwright 语义下 click/type/press/scroll/hover/waitFor（自动等元素）/多 tab/下载管理全套齐，且带 auto-waiting——这是对 agent 最友好的部分（CDP 裸面要自己写等待/重试）。

### 5.3 与面板的关系

- B 独立形态驱的是**另一个隐形浏览器窗**（msedge channel 独立进程）：与用户可见面板割裂，agent 干活用户看不见、登录态/Cookie 与面板两套——体验上是"两个浏览器"。
- B 融合形态（connectOverCDP 连面板端口）则与 A 同窗，只是把协议层换成 playwright 语义——依赖 qwen 已验证的 transport 能力【仓内实读】。

## 6. 五维对比

| 维度 | A（面板 CDP 通道） | B（独立 playwright 进程） | B 融合（connectOverCDP 连面板） |
| --- | --- | --- | --- |
| 启动开销 | 零（面板已在）；连 ws 毫秒级 | 子进程+channel 冷启 ~0.5-1s（常驻可摊销） | 同 A + playwright 握手 ~200ms |
| 依赖体积/便携 | **+0MB** | +13.4MB（playwright-core，零子依赖）；不下载浏览器 | +13.4MB |
| 隔离性 | 端口暴露面需 data directory 收口；壳崩面板亡（host 不亡） | 驱动 worker 崩溃不带走 host；浏览器进程与壳彻底分离 | 同 A（驱动逻辑在 host 内/子进程，浏览器还是面板） |
| 可编程面完整度 | navigate/screenshot/extract 现成；click/type 走 Input 域或 evaluate 注入，**等待/重试自己写** | **全套 + auto-waiting + locator + 下载** | 同 B（驱面板） |
| 与可见面板关系 | **同一窗**（agent 与用户看同一面板） | 隐形独立窗（双浏览器体验割裂） | **同一窗** |

## 7. 结论与分期建议

**推荐：A 扩展为主、B 融合为增强的分期路线。**

理由（对齐项目既有约束）：

1. **资产复用最大化**：面板承载（T-P3-169）与 CDP 工具族（T-P2-407）都已落地且真机走过查，中间只差"端口暴露 + 端口发现 + 工具接线"三件薄胶水；`scheduler/browser.ts` 的审批/域白名单/deadline/NOTICE 安全面已按项目纪律建好。
2. **零依赖纪律**：便携包 187.6MB 刚瘦身完（node-pty 61→30MB），13.4MB 的 playwright-core 在"确实需要 locator 语义"之前不该预付（AGENTS.md"不为未来可能用到预埋设计"）。
3. **同窗体验**：zcode/pi-desktop 两个最完整参照都裁决了"agent 驱动用户可见面板"；B 独立隐窗与既有面板产品形态冲突。
4. **风险已知且可控**：target 断连（真机已踩）、端口无鉴权（data directory 隔离）、headless 缺席（本就做可见窗）——都有明确缓解路径。

分期：

- **第一期（A 扩展，一个批次可容）**：
  1. `browser.rs`：`browser_create` 加 `.data_directory(<便携>/data/browser-profile)` + `.additional_browser_args("--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --remote-debugging-port=0")`；`browser_destroy` 后收口；可选 `on_download` 落下载目录；新增 command 返回 `DevToolsActivePort` 读到的端口（真机复验为第一验收项）。
  2. `scheduler/browser.ts`：`connect` 工厂实现（读端口 → `cdpWsUrlOf` → `CdpConnection`），补 click/type 两动作（`Input.dispatchMouseEvent`/`Input.insertText` 或 evaluate 注入），加 `/json/list` target 发现与断线重连。
  3. 接线：browser 三~五工具进主对话工具注册表（`src/kernel/tools/builtin/index.ts` 的 `BUILTIN_TOOL_NAMES` + 装配；审批回调接 C 族审批卡，域白名单接 D3 策略）；注意 scheduler 是 managed 域（architecture-policy.json：scheduler 只依赖 kernel），装配落 host/装配面不落 scheduler。
- **第二期（B 融合，触发条件驱动）**：当 click/type 的裸 CDP 面被实战证明不够稳（等待/选择器缺失导致操作失败率高）时，引 playwright-core（13.4MB）进 browser-driver 子进程，`connectOverCDP` 连同一面板端口，把工具面升级为 locator 语义——第一期对外的工具名与审批面不变，只换引擎。
- **不做**：B 独立隐窗（产品形态割裂）；playwright 下载 chromium（便携体积不可接受）；qwen 式扩展+Native Host 基建（V1 不驱用户日常 Chrome，复杂度无收益）。

遗留待验：`--remote-debugging-port=0` + 专属 data directory 下 `DevToolsActivePort` 的落位与时机（首次真机验收）；隐藏/视口外 webview 的 `Page.captureScreenshot` 成功率；`browser_show` 拖拽跟随期间 CDP 操作的稳定性。
