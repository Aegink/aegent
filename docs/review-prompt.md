### 六、工作方式（**严格遵守**）

1. **先确认存在，再下判断。禁止只依据记忆写路径。** 引用的路径与行号必须是你实际读到的。
2. **某仓本机没有就写「缺失」，不要假装分析过。**
3. **不要大段粘贴上游源码**；最多 20 行说明一个机制。
4. **所有数字必须由脚本产出**（`tools/count-features.sh` / `tools/check-doc-links.sh` / `tools/sample-anchors.sh`），不手工数。
5. **跨仓结论必须先把所有仓都搜过才能下。** 只查了一部分就写"仅查了 N 个仓"。
6. **引用结论必须锚定 commit**（`oss/SOURCES.lock`），否则不可复现。
7. **不要修改 `docs/requirements.md`** —— 见 §三A 的理由。你的产出是报告 + 填好的核对清单。
8. 效率：`oss/` 约 2.5GB，全仓 `find`/`grep` 很慢。
   - 用 `--exclude-dir=node_modules --exclude-dir=.git --exclude-dir=target --exclude-dir=dist`
   - 优先用 `tools/probe-repo.sh`、`tools/sweep.sh`
   - **不要在运行中编辑正在跑的脚本**（bash 按字节偏移读文件，改了就错位）
   - 判进程是否在跑用 `Get-CimInstance Win32_Process`，**`ps aux | grep` 在这台机器上看不到部分 bash 进程**

### 七、防错清单（前人踩过的具体坑）

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| 泛词正则 | `abort`、`leaked` 命中大量 CHANGELOG 与文档，噪音淹没信号 | 搜**实现痕迹**（目录名、具体类型名），或要求关键词与限定词同现 |
| 手工计数 | 数功能数错两次 | **写脚本统计** |
| 只看部分仓 | 得出"需自研"的错误结论 | 结论前**先跑一遍全仓搜索** |
| 编号冲突 | 多轮追加后同一 ID 两条需求 | 新增项**当场进主表**，用 `tools/count-features.sh` 核对总数 |
| **引用路径过时** | 文档里的路径上游已改 | 跑 `tools/check-doc-links.sh`，**0 失效**才算引用可信 |
| **行号漂移** | 文件对但行号指到别处 | 这正是本次复核的主任务；判 ⚠️ 要**给出正确的行号** |
| heredoc 截断 | 单次 `cat > f <<'EOF'` 内容过多会被截断，报 `unexpected EOF` | 拆成多段，每段 ≤ 100 行 |
| `.gitignore` 排除目录 | 连 `!豁免` 一起吞掉，锁文件静默未跟踪 | 写 `oss/*` + `!oss/SOURCES.lock`，而非 `oss/` |
| `cmd \| tail` | 缓冲区不刷，日志看起来 0 字节像卡死 | 输出重定向到文件 `> out.txt 2>&1` |
| Python 写文件 | Windows 上 `io.open(p,'w')` 会写成 CRLF，与 `eol=lf` 冲突 | 写 `.md` 用 `newline='\n'`，或写完后统一归一化 |
