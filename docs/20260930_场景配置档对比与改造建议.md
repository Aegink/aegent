## 一、参考项目的"场景/预设"长什么样

### 1. cc-switch（直接锚点）——指针快照 + 自动重拍，切换器语义的完整范式

- **两层分离**：供应商 = 零件（资产层），Profile = 组合（场景层）——**payload 只存指针
  不存拷贝**（providers 槽 = 供应商 id；apply 时查实时配置），供应商编辑后所有引用它的
  场景自动跟随（provider.rs / services/profile.rs）。
- **四槽位快照**：providers（每应用当前供应商指针）/ mcp（启用集）/ skills（启用集）/
  prompts（激活项）；**三态语义**：`None = 该组从未拍过（应用时不动）` / `Some(空) =
  拍到空集（应用时清空）` / `Some(值) = 具体目标`——解决"新场景误清空现有状态"痛点。
- **切走自动重拍旧场景**（autosave-resnapshot）：切换前把当前状态重拍进旧档——
  "场景切换"变成无损往返，用户永远不必手动保存场景。
- **最小 diff 应用**：只 toggle 目标态 ≠ 当前态的项，幂等；单项失败收集 warnings 继续
  （best-effort），不搞全有全无。
- 交互：单选下拉即点即切（无确认弹窗）、托盘子菜单勾选态、管理弹窗重命名/排序。

### 2. CLI 系 profile——三条纪律

- **codex**：profile = 用户层之上的完整配置层（分层栈 user(20) < profile(21) < 项目(25) <
  会话 flags(30)，只写差异项深合并）；**项目层禁止选 profile**（denylist 防供应链注入）；
  权限档独立成体系（内置 `:` 前缀三档 + extends 继承 + 企业 allowlist + TUI 会话热切）。
- **grok-build**：项目配置**只能新增档名、不能改写全局已有档**（防恶意工作区掏空）；
  **会话与档绑定**——resume 时换档直接拒绝（"会话内权限语义不漂移"）；继承仅单层且限
  内置基档（天然无环）；错误信息内嵌可复制的示例配置。
- **hermes**：profile = 整租户（目录隔离凭据/记忆/人格/会话）——重形态，单用户桌面应用
  不需要；但其"切换语义随运行时模式变化"（代理接管态切换退化为改路由指针）值得记档。
- **deepseek-harness**：四级命名配置（出厂 bundle / 用户 profile / 临时 overlay / 会话级
  agent preset）；行 id 最后写胜出、整行替换（无深合并歧义）；"模式差异行绝不放共享层"。

### 3. 桌面/权限视角

- **opencode**：**场景 = 一等实体**——一个 agent markdown = 权限 ruleset + 提示词 + 模型 +
  参数的命名包（plan/build 就是两个内置场景）；per-message 切换（Tab 循环），成本趋近零。
- **zcode/qwen**：模式 = 硬编码内置预设（四/五档），不可用户扩展；qwen 的信任门联动
  （未信任目录只允许 default/plan 档）+ 仓库配置三层防放宽。
- **共性**：权限模式本身就是一种内置场景；用户场景档 = 在模式之上再捆模型与资源面。

## 二、我方现状

**已有（U19/T-P3-121）**：ProfileEntry = { 档名, defaultProvider（指针✓）, defaultModel,
审批超时, 网络档, 沙箱模式 }；切换 = 批量写生效段（新会话生效）；侧栏快切下拉；"填入当前
生效值"快照建档。上轮评估结论：与供应商**不是凭据式重复**（指针 vs 资产），缺的是概念完整性。

**断点（"和场景这个词的功能不一样"的根源）**：
1. **不捆权限模式**——"写代码场景 = Claude + 全自动 + 禁网"这种典型需求做不到（只能捆
   超时+沙箱+网络），概念半残的直接原因。
2. **建档表单手输名字**——供应商/模型字段是文本输入（拼错静默失效），不是从注册表下拉选。
3. **切换不热应用**——只落盘新会话生效；而权限模式/沙箱模式的 config/refresh 热切换通道
   与 J6 model/switch 会话换模协议**都已存在**，场景切换本可全链热应用。
4. **无自动重拍**——在权限页改了模式后，旧场景不知道；cc-switch 的"无损往返"缺失，
   用户得手动维护档案。
5. 无 MCP/技能启停捆绑（cc-switch 四槽位之一）——可选扩展。
