# 会话笔记：T-P3-170 多任务并发架构落地 + 设置页行卡统一
- 日期时间：2026-10-05 01:00
- 工具/路线：ZCode 主会话（架构改造 + WS 实测 + IAB 截图）
- 目标：用户反馈两条——①设置页"对话与输入"UI 简陋不统一；②同项目/跨项目多任务并发"完全没做好"（新建不见/已有的不见/新建慢/状态不实时）。第②条全面对齐 pi-desk 任务模型。

## 步骤与观察
1. 侦察定案：旧架构=每会话一 host 进程（T-P3-166 工作池），UI 单 WS 连接只能看一个会话——实时并发态结构性不可行；createTask 走 restart_host（杀树+等端口≈秒级+旧会话镜像全丢）= "新建不见/已有的不见/新建慢"三症状共同根因。
2. pi-desktop 对应物：单 sidecar + Map<sessionId, Runtime> 多路复用。我方落法：host 进程内 child 池（bridge agentFactory 懒派生，每会话一个 agent-child 进程，同 host 常驻）。
3. host 端改造：bridge.ts per-session 泵/pendingPrompts/lastPendingPromptId；send() 删 UNKNOWN_HOST_SESSION 硬拒；租约保持连接面语义（持约端可驱动任一会话——跨端竞写弱化记档）；事件镜像/归属/N5 通知全部按事件会话；killAllChannels 收束池；child 崩溃即摘池下次重派生（--db 持久恢复）。
4. task-create op：会话行即刻落库（db.createSession=INSERT OR IGNORE+upsertIndex）+ setSessionProject——零事件任务立现清单；projectTasksOp 镜像标题兜底（库行已存在但标题空时用镜像首条 user 话语补——write-behind 窗口）。
5. query 读面统一 mergedStream：镜像+库 seq 去重合并（库行打底、镜像覆盖、seq 排序）——events/review/usage 三 op 一个读面，历史/活跃/重启后会话恒完整。
6. UI：handleEnvelope 按 envelope.sessionId 分发（非当前会话不进主流、不污染 agentState）；window.__sessionStates 全会话状态表（turn 边界/审批态记账）驱动侧栏任务行状态点；审批卡带来源会话（card.dataset.sessionId——后台任务审批答复不错路由）；switchToSession 纯前端（setSessionId+events 恢复+busy 回放+refreshSidebar，零重连）；createTask 走 task-create 即建即进。
7. 设置页：chat/network 分节重写为基准行卡体系（group-title+row-list+row+row-copy+row-control+tabs-pill+switch）——根因是 T-P3-165 落地时发明了 CSS 里不存在的 .settings-row/裸 .tab-group 类（塌陷成原生控件堆叠），.card 类是聊天流审批卡样式（金色边框来源）。顺手修 close-behavior 段 toast 未导入的 ReferenceError。
8. 验证：2076 测试绿（含新增 bridge 多会话路由用例：双 child 各自回声、事件归属严格分流、池化复用断言）；WS 隔离 host 实测全 PASS（task-create 立现/双会话并发轮/事件归属 9 事件完整/恢复视图合并读/标题兜底 hello-b）；IAB 截图设置页与权限档分节视觉一致。

## 结论（一行）
- 单 host 多会话并发落地：新建毫秒级立现、切换零重连、后台任务侧栏实时状态点、事件归属全程分流——三症状（新建不见/已有的不见/新建慢）根治，commit 4c8b40a。
