# UI 全面升级方案（2026-09-29 用户裁决）

> **缘起**：用户实际走查判定"所有页面都很简陋，完全不像一个成熟的产品"，指令"参考多个仓库全面升级 + 全面排查 + 写 UI 全面升级文档"。本文档是排查结论与分批实施方案；**实施前需用户裁决技术路线（§5 方案 A/B）**，裁决后按 §6 展卡分批实施。
> **约束回顾**：全局约束 3 = 零前端构建链（不引 React/Vite，`ui/` 原生 ES module）——这是 P3 展卡时的既定裁决，本次升级是否维持见 §5。
> **红线不变**：参考仓 UI 全部 🔴 只学行为与视觉形态、一行代码不摘（ZCode Apache-2.0 可摘但组件是 React+Radix 形态，直接摘译成本高于重写——统一按行为映射）。

## 三、升级方案（三批，每批一张卡、可独立验收）

### 批次 A：设计系统与布局架构（地基——后续两批的前提）

1. **设计 token**（`ui/theme.css` 新建，全站唯一取色处）：色板对齐 ZCode 暗色体系（背景三级 `--bg-0/1/2`、边框两级、文本三级、强调色、成功/警告/危险语义色）+ 圆角（6/10/14px 三档）+ 阴影两级 + 4px 间距栅格 + 字体栈（界面/等宽双栈）+ 尺寸常量（侧栏宽/行高）；亮色主题同 token 映射（U14 既有 `data-theme` 机制保留）。
2. **布局架构**：顶栏状态栏 → **左侧边栏**（顶部：会话/项目分组树〔消费 op:"sessions" 既有面〕；底部：设置/通知入口+版本号——ZCode 同构）+ 主内容区 **hash 路由化**（`#chat` / `#settings/<section>` / `#usage` / `#work/<tab>`——深链可达、前进后退可用）；设置从右抽屉迁出为**页面**（左侧二级分类导航三组：基础设置 / Agent 能力 / 数据与系统——zcode 截图同构）。
3. **组件类库**（`ui/components.css` 新建）：按钮（主/次/危险/幽灵四态）、输入/选择/开关/分段控件、卡片、行式设置项（label+hint+控件右对齐）、标签/chip、表格、空状态、加载态（骨架行）、对话框（替代原生 confirm——迁移各删除确认）、toast 重做；**图标**：内联 SVG 精选集（~20 枚线性图标，单色 currentColor——零依赖）。
4. **验收**：token 全站取色 grep 证伪（style.css 无裸色值残留）+ 路由深链用例 + 视觉走查列确认清单。

### 批次 B：设置中心页面化 + 管理页重做（对齐 ZCode 设置包）

按 §1.2 逐页迁移与重做（每页 = 迁既有逻辑 + 套新组件类 + 对齐参考锚形态）：设置骨架（三组分类导航）→ MCP 页（状态点/开关/命令行）→ 子智能体页（分组卡片/空状态引导/工具数徽标）→ 技能页/提示词库（卡片+搜索）→ 快捷键页（绑定行+搜索）→ 插件页（安装表单模态化）→ 供应商/凭据页（连接测试模态——对齐 opencode dialog-connect-provider）→ 用量**升级为统计页**（统计卡片行 + SVG 每日趋势线 + 模型用量甜甜圈 + 近 7/30 日切换——纯 SVG 手绘零图表库；消费 op:"usage" 既有面）。既有 app.js 逻辑（settings patch/防抖/校验）全部保留——**本批是呈现层重写，不动数据面**。
**验收**：每页对齐参考锚的形态要点逐条走查清单 + 既有 settings/server e2e 回归全绿（wire 面零变化）。

### 批次 C：主对话流与面板升级（对齐 ZCode 主界面）

聊天流排版升级（气泡密度/代码块标题栏/表格样式/引用块/任务卡片化工具调用/日期分隔）、会话侧栏（历史分组+搜索+项目树）、工作面板/通知/搜索面板套新组件类、首屏空状态（ChatEmptyState 形态：欢迎语+能力快捷入口）。
**验收**：同上走查清单 + ui-render 既有 XSS 十例回归（渲染安全面零变化）。

## 四、不改什么（升级边界）

- **wire 面/内核零变化**：全部页面消费既有协议面（settings 十九段、query 六 op、request/response 流）——UI 升级不产生新协议需求（每日趋势聚合若需 host 补 byDay，届时单点定形）；
- **渲染安全面零变化**：markdown 禁 HTML 透传、href 白名单、用户输入 textContent——批 C 重排版不动 render.js 管线；
- **键盘/快捷键语义零变化**：keymap 注册表照旧（视觉胶囊化）；
- **主题机制保留**：`data-theme` 亮暗双主题继续全端一致。

## 五、技术路线（裁决点）

- **方案 A（建议）**：维持**零构建链**，手写设计 token + 组件 CSS 类 + 内联 SVG 图标 + hash 路由。代价：组件交互（下拉/对话框）手写；收益：全局约束 3 不破、包体不变、无 Node 构建依赖（SEA 教训的延续）、改样式即改文件。
- **方案 B（备选，需用户明示推翻约束 3）**：引入 Vite + 轻组件库——获得组件生态与热更新；代价：构建链进包（壳资产链重验）、THIRD_PARTY 扩容、与"改文件即生效"的既有调试工作流断裂。
- **图表一律纯 SVG**（趋势线/甜甜圈/热力图均可手绘，数据量级 ≤ 百点）——两方案下都零图表库。
