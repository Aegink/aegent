## 借鉴方法的四条经验（接 P0 三条 + P1 三条 + P2 四条，P3 增量）

14. **"数据面已在、缺管理 UI"是产品化批次的典型增量结构**：U15 变更评审（流内事实已有）、U17 MCP 向导（mcp 域已有）、U18 辅助模型卡（C42 已有）、U23 子智能体（H1-H5 已有）——展卡时先核对数据面是否在位，产品卡=消费端+编辑器+开关，内核零新增机制是常态（U23 工具集直接走 C25 activation 是"不建新机制"纪律的兑现）。
15. **管理面的行数纪律要预埋拆分位**：16d 五卡三度触顶 400 行上限，全部当场拆域文件归还（protocol-settings/agent-child-config/instructions+skills+speech-gateway）——settings-gateway 类从 193 行长到 419 行再回 338 行，"每面一文件"的拆分模式在批次内固化；提前为持续扩张的 op 闭集建独立域文件，比事后压缩注释便宜。
16. **编辑器写回必须双防线 + 原子替换**：U22 技能 / U24 指令与规则两类文件写回共用同一模式——parse 层形状校验（slug/白名单闭集）+ gateway 层业务校验（重名/字节上限/路径收敛）+ tmp 原子替换；"配置是用户权威"（保存不阻断）与"坏行不装载"（装配 fail-closed 跳过）分层，避免把校验做成写入障碍或把脏数据放进装配。
17. **flake 记档的价值在收口时兑现**：16b 记档的两例基建 flake（llm-replay 计时抖动/complexity 收尾竞态）在 16d 收口按记档建议顺手修复——全量运行从"两轮全绿在案"变成"稳定 exit 0"。记档不是免责，是把"下次顺手修"变成可执行的账。
