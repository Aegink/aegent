## 一、参考项目的"沙箱"长什么样

### 1. 总览：行业已收敛成四层

| 层 | 是什么 | 谁做了 |
| --- | --- | --- |
| 策略层 | 模式档位（文件效果 × 网络开/关），平台无关 | 全员（词汇收敛，见 §2） |
| OS 强制层 | 真正"管住"任意子进程的底层 | codex（Seatbelt/bwrap+seccomp/Windows 受限令牌）、deepseek-harness（Windows ACL）、qwen-code（bwrap+docker）、grok-build（Landlock/Seatbelt）、**我方已建成未接线** |
| 审批联动层 | 越权出口：沙箱拒绝→审批→放宽重试 | codex（escalation+审批即落规则）、deepseek-harness（escalation+justification 成对）、**我方契约面已在** |
| UI 层 | 模式卡/状态行/自检/白名单管理 | pideck（最完整设置页）、codex（/permissions+/status）、qwen（sandbox report/verify） |

### 2. 档位词汇已行业收敛（我方词汇恰好一致）

`read-only` / `workspace-write` / `danger-full-access` 三档 + **网络独立一档**（开/关）
——codex、deepseek-harness、qwen-code、grok-build（+strict/off）、agentscope
（BYPASS 档注明"仅容器内用"）五家用词几乎相同。**我方 SandboxMode 三档词汇与
行业完全一致，无需改名**；差异只在"有没有接上真引擎"。

### 3. 各家亮点精选（按可借鉴度）

- **codex（40eac3c）——架构最完整**：策略/后端彻底解耦（同一 PermissionProfile
  可被 5 种 SandboxType 表达，表达不了 fail-closed 拒跑而非静默放宽，windows.rs:47-100）；
  升级即审计（沙箱拒绝启发式识别 denial.rs → 带理由审批 → 去沙箱重跑 → 审批结果可
  沉淀为 execpolicy/域名规则）；防提权细节内建于策略层（.git/.codex 只读子路径、
  rename/fcntl/TMPDIR-symlink 逃逸封堵）；TUI 无裸沙箱命令，是 `/permissions` 预设
  选择器（档位=审批策略×沙箱模式成对绑定）+ `/status` 与状态行常驻显示当前档。
- **deepseek-harness（0010283）——Windows 蓝本**：`sandbox-windows-acl` 包 =
  capability-SID allow ACE + 父目录 delete-deny + Low integrity + 私有 temp 显式授予
  （null 即禁 temp）+ 决策文档；enforcement 诚实分级 full/partial；无后端时
  `SANDBOX_UNAVAILABLE` 绝不裸跑；生效策略**注入模型上下文**（模型知道边界，
  减少无效尝试）；会话级模式热切换 + 重放存活。（我方 backend.ts 头注释明说契约
  形状取自它——同源。）
- **qwen-code（40ef07a）**：`qwen sandbox` 子命令三合一——report（当前生效策略）/
  verify（验证内核边界真的生效）/ 试跑单条受限命令；`tools.executionSandbox =
  { backend, filesystem, network }` 二维档位配置。
- **grok-build（07e35a3）**：profile `extends` 继承 + 自定义 deny glob 内核强制；
  **项目配置不能重定义全局 profile 名**（防恶意仓库架空用户配置）；运行时自检
  enforce 真实生效（read_deny_verify.rs，fail-closed）。
- **pideck（d1bd0c9）——设置页形态最完整**：安全总开关 + 预设三档（off/standard/
  strict）+ 每档可改：工具×动作矩阵（8 工具 × allow/ask/deny 下拉）+ bash 危险命令
  正则清单 + 路径策略（unrestricted/workspace/custom + 白名单目录 + 黑名单目录 +
  敏感文件保护开关）；**全局默认 + 会话底栏一键切档**双层作用域。
- **zcode（872ad96）**：OS 沙箱层已拆除但中间层极厚——审批"记住"三档
  （once/项目持久/会话级）+ 高危根命令集不生成前缀规则 + readonly 语义分析管线；
  值鉴的是"审批选项策略"（高危工具可声明 no-always-allow）。
- **opencode（18ef3cc）**：无 OS 沙箱，权限完全声明式——agent 即权限集；审批
  always 由工具**自报可记住的 pattern**（bash 是命令前缀 `npm install *`）。
- 其余：hermes-agent（Docker+UID 映射+凭据路径黑名单）、agentscope（8 后端可插拔
  +隔离粒度 per_session/per_agent/per_user）、mini-swe-agent（env 白名单转发+
  容器自动清理三件套）、pi-mono（escape-audit 自检命令）、kimi-code/cc-switch/
  mini-agent（无沙箱）。

### 2. 断点（"和沙箱这个词的功能不一样"的根源）

1. **`bashSandbox` 生产装配零接线**——全仓唯一消费点是
   `src/kernel/tools/builtin/index.ts:105` 的选项声明；agent-child 装配只接了
   `networkPolicy`（agent-child.ts:398），**没有任何地方传 bashSandbox** → 生产
   bash 走 env 直通；模型带 sandboxPermissions 升级申请只会得到"没有沙箱装配在场"
   的类型化拒绝。**引擎建好了没装进车。**
2. **helper 不在发行链**——`DEFAULT_HELPER_PATH` 指向 cargo target 目录，
   `dist/portable/` 无 win32-sandbox-helper.exe，host/tauri 无 helperPath 引用 →
   即使接线，用户机也会走"缺席→降级弱兜底"分支（用户桌面版实际永远不可强制）。
3. **`sandboxMode` knob 是观测面**——session-config.ts:29 自认"bash
   defaultMode 构造定死"：权限模式五档（刚做的 A）里 read-only/auto 档携带的
   sandboxMode 值**没人消费**，切档不改变子进程任何实际约束。
4. **writeWhitelist/readRoots 无配置面**——PathGuard 支持，装配只传 workspaceRoot；
   UI 无白名单管理（codex `--add-dir`/writable_roots 对应物）。
5. **D16 provision 无 UI 引导**——deny 档对子进程的真实强制（WFP）需管理员一次性
   provision，现在只有 README 弱承诺文档，UI 无状态显示、无引导。
6. **UI 只有三行**——网络档下拉（allow/deny）+ 工作区输入框 + 事件库输入框。
   您看到的"一个页面一个功能"就是这么来的。

### 3. 已知边界文档（齐备，改造时沿用）

`sandbox-path-limitations.md`（7 条——工具层覆盖面与 fail-closed 语义）+
`shell-semantics-limitations.md`（8+4 条——静态分析做不到的清单，含 msys bash
沙箱态结构性不可用→PowerShell 宿主正路）。**弱承诺纪律（不假装已管住）是既有
红线，改版 UI 必须延续这份诚实。**

## 四、实施记录（2026-09-30 用户裁决"全做（A~F）"）

- **A 沙箱模式三档 + 生产接线**：`createRoutingBackend`（containment.ts——全自动档恒 local 直通 / 受限档走 win32 受限令牌后端 / helper 缺席 fail-closed `SANDBOX_UNAVAILABLE` + 可见降级告警）+ `resolveSandboxHelperPath`（env → 发行包伴随位 → 仓库约定三段式）+ 装配接线（assembly.ts `bashSandbox`/`pwshSandbox`——`defaultMode` getter 活读 `configStore.sandboxMode`，agent-child `--sandbox-mode` 注入 + `sandboxWiring: true` 武装）+ pwsh 同接（无升级面——升级只在 bash 一侧）+ 子代理透传（同后端同档、无审批通道——升级在子代理语境 fail-closed）+ **helper 进发行链**（build-host-bundle.mjs 拷贝 `win32-sandbox-helper.exe` → dist/portable，缺席打包告警不阻断）+ 私有 temp 目录按 canonical 工作区派生落盘 + `SandboxUnavailableError` 在 bash/pwsh 显式结算（未启动不标 started）。**塌缩语义**：helper 缺席时配置的受限档按全自动降级（每档一次 warn + 自检常显）——D5 fail-closed 只对"审批过的升级"绝不放宽。
- **B 自检面板**：`sandbox-doctor` op（protocol/bridge/gateway 三层）+ `settings-sandbox-doctor.ts` 域文件（host 行数纪律拆分位）+ 沙箱页自检卡（生效模式 × 强制后端一览 + doctor 四项检查 + 修复命令一键复制）。
- **C 网络档增强**：deny 档强制面两态文案（工具层拦截 ↔ OS 级强制在位）随自检联动刷新 + IMDS/SSRF 恒拦说明 + provision 引导入口。
- **D 路径白名单**：`settings.sandbox.writeWhitelist`（非空字符串数组 parse + 去重保序）+ `--write-whitelist` 逐条注入/解析 + PathGuard `writeWhitelist` 装配透传 + UI 增删行列表；保护名单（.git/.agents/.codex 等）只读展示走 doctor 载荷。
- **E 审批联动收尾**：审批卡升级徽标（`chip-warn`）+ 理由展示行（`card-justification`）+ 审批历史升级标记（`policy-audit-op.ts` 域文件——从 tool/call 原始参数串提取 sandboxPermissions/justification，SANDBOX_ESCALATION_DENIED / SANDBOX_UNAVAILABLE 拒绝入史）。
- **F 作用域双层**：`profiles[].sandbox.mode`（parse 闭集校验 + 建档表单 + 描述行展示）+ 模式卡会话热切换（config/refresh 既有通道——REFRESHABLE_CONFIG_KEYS 已含 sandboxMode）。

**验收**：vitest 全量 **1842 passed / 7 skipped**（209 文件；新增 11 用例——路由后端三态/helper 解析/活 defaultMode/pwsh 沙箱/settings parse/launch argv/profiles mode）+ `architecture:check` 0 error（host requires 追加 sandbox 申报 + bridge/gateway 行数拆分：policy-audit-op.ts / settings-sandbox-doctor.ts）+ 走查实测（模式卡切换 toast + 落盘 `{"mode":"workspace-write","writeWhitelist":["F:/shared-libs"]}` + 自检卡四项渲染，helper 走发行链路径解析成功 + WFP 未 provision ▲ 如实呈现）+ 产物四步链（build:single + 签名 tauri build + 壳哈希一致 cp + 安装器/.sig）。

**记档**：①tauri 签名环境变量 `TAURI_SIGNING_PRIVATE_KEY` 传**密钥内容**（文件末行 base64）而非路径——plan-p3 的"传路径"记录不准确；②受限档 + helper 缺席的降级是**可见塌缩**而非静默放宽（D14 纪律），自检卡常显；③升级审批在子代理语境 fail-closed（无人的通道不可升级）。
