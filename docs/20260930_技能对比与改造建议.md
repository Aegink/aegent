# 技能页对比与改造建议（2026-09-30）

> 调研阶段产物（用户规则：先报告后改码）。参考仓：zcode（16 源扫描表）、pi-desktop
> （四 tab 导入工作台 + 市场）、opencode（三源统一抽象 + URL 远程源）、cc-switch
> （SSOT 投影 + scan_unmanaged + 双通道发现）、kimi-code、qwen-code、codex（快扫增量）。
> 全部结论附 file:line。

## 0. 结论一句话

用户要点（**外部技能源扫描导入**）在四个仓全有成熟先例，形态高度一致：目录扫描 →
候选（SKILL.md + frontmatter）→ 勾选 → **整目录复制或 symlink/junction** 进自家技能根，
冲突绝不覆盖；我方内核（多根扫描 + 128KB + 原子写）已具备全部承接面，改造规模 =
1 个新 host op（扫描 + 导入执行）+ 技能分节 UI 增强（导入模态/删除/种子模板/字节计），
零新增依赖。

现状（内核 `src/kernel/skills.ts`：`<workspaceRoot>/.zcode/skills/` 递归发现 SKILL.md
〔有 SKILL.md 的目录即叶子〕、frontmatter 行解析 name/description/tools、diagnostics

诊断行）+ 编辑器 + 来源目录增删；消费 = 系统提示清单〔新会话生效〕+ skill_load 工具
直读 + 子代理透传）。

| 能力 | 我方现状 | 差距 |
| --- | --- | --- |
| 导入 | 无 | 全缺（四仓皆有，形态一致） |
| 删除 | 无（停用≠删除，删文件须手动） | zcode/pi-desktop 均有，含安全护栏 |

## 3. 参考仓要点

### 3.1 zcode（16 源扫描 + symlink/copy 双模式）

- **管理页**（`packages/ui/src/settings/SkillsSection.tsx`，1007 行）：行 = 图标 +
  名称/描述 + 启停 + 删除（确认弹窗）；插件技能分组展示；详情为**只读弹窗**（无编辑
  UI——服务层无内容写接口）；头部动作 刷新/导入/新建；诊断琥珀色可折叠横幅
  （"X errors / Y warnings"，13 个诊断码，`skills-types.ts:39-52`）。
- **schema**：frontmatter 只消费 `name`/`description`（严格 YAML + **宽松行级回退**，
  兼容中文未加引号 description——`skillsService.ts:296-385`）；agent 端
  `SAFE_FRONTMATTER_KEYS = [name, description, when_to_use, license, metadata]`
  （`adapters/src/skills/index.ts:20-35`），`when_to_use` 拼进系统提示行；未知 key
  不报错。description ≤1024 字符、正文上限 100,000 bytes。目录纪律：**不强制一技能
  一目录**——递归深度 ≤8 找 SKILL.md，支持分组目录 `root/<group>/<name>/SKILL.md`，
  跳过 node_modules/点目录（`skill-scan-policy.ts:21-50`）。
- **导入（重点）**（`settingsSyncService.ts` + `ExternalAgentImportDialog.tsx`）：
  - 扫描源表 `SUPPORTED_SKILL_AGENT_SOURCES`（148-181 行）16 个外部 Agent，全部是
    **目录**：claudeCode `~/.claude/skills`、codexCli `~/.codex/skills`、openCode
    `~/.config/opencode/skills`、openClaw `~/.openclaw/skills`、augment、continue、
    goose、qwenCode `~/.qwen/skills`、qoder、windsurf `~/.codeium/windsurf/skills`、
    trae、kiroCli、roo、codeBuddy（各配项目级 `<ws>/.xxx/skills`）。
  - 候选 = 每个 SKILL.md 所在**目录**（有界遍历复用技能发现；名称/描述 YAML+宽松
    回退，顺带读 version 显示徽标）。
  - 打开模态自动扫 + 刷新按钮；**symlink / copy 二选一下拉，默认 symlink**
    （`ImportModeSelect`，ExternalAgentImportDialog.tsx:830-885）：技能按**整目录**建链
    ——Windows 用 junction、其它平台 dir symlink（`importSkillDirectory`:547-577）；
    copy = `cp recursive errorOnExist`。
  - 冲突**绝不覆盖**：目标已存在 → skip `targetExists`；目标根内同名（name 小写化）
    → skip `sameNameExists`；**扫描阶段就预判可导入性**，不可导入项不可勾选。
  - 写入作用域：全局 `~/.zcode/skills` / 项目 `<ws>/.zcode/skills` 下拉；结果页
    imported/skipped/failed 三色统计 + 逐项状态。
- **删除安全护栏**（`skillsService.ts:1199-1235`）：删除前 realpath 展开祖先链，限定
  只能命中受控技能根——防软链祖先穿越 rm。symlink 技能删除只删链接不动目标
  （`sourcePath` 保留链接本体）。
- **没有的**：技能编辑器、批量启停、用户级附加根 UI、首启自动扫描（已移除）。

### 3.2 pi-desktop（四 tab 导入工作台 + 市场面，桌面壳最同构）

- **管理页**（`AgentSkillsPage.tsx`，622 行）：Global/Project 双组分栏（组头 = 目录
  路径 + 计数 + 导入按钮）；行 = 启停（**乐观更新失败回滚**）+ 编辑 + 行菜单
  （Reveal 文件管理器 / **Move 作用域转移** / 两段式删除）+ level 徽标 +
  `source: "imported"` 导入徽标。无 Test、无诊断面板。
- **编辑器**（`SkillEditorSheet.tsx`，335 行）：name/description/body + enabled；
  **MAX_SKILL_BYTES = 128KB**（与我方同值）；**字节计数器实时显示，>80% 变黄、
  超限变红**（:268-281）；slug 前端预览；**新建时输入 name 即一次性 seed body**
  （`skillTemplate` 三段骨架：## When to use this / ## Steps / ## Notes——"空编辑器
  教不会格式"，nameTouched 门控不覆盖已写内容）。
- **schema**：frontmatter 只有 name + description（name 120 字符/description 400
  截断）；**目录纪律：只扫 skills 根一层**（平铺 `<id>.md` 与目录 `<name>/SKILL.md`
  两种形状）；MAX_SKILLS=128。
- **导入**（与 MCP **同一页不同 tab**——四 tab 工作台 sessions/models/skills/mcp，
  面板常驻扫描结果跨 tab 存活）：源 = claude-user `~/.claude/skills`、claude-project、
  pi-user `~/.agents/skills`、pi-project；每源上限 128 候选；候选带 warnings
  （missing frontmatter/name/description）；**mode 下拉 copy（默认）/link**（Windows
  按 dir/file 分 symlink 类型）；冲突三层防线（host bail → 逐条回放错误匹配
  /already exists/ 归 skipped 桶 → UI 三计数 toast）；批量导入后**自动重扫让已导入
  行消失**。另有"导入文件/导入目录"原生单选入口。
- **Move 语义**（`user_skills.rs:619-734`）：global↔project 是**移动不是复制**；目标
  同名自动改名（只重写 frontmatter name 行、其余逐字节保留）；落地用"模拟真实扫描"
  验证，扫不出来整体回滚。
- **技能市场**（`SkillMarketPanel.tsx`，880 行）：7 个默认 GitHub 源（git/trees API
  找 SKILL.md + jsDelivr CDN 拉文档）；自定义 catalog JSON 源；**安装前全文预览**
  （超限禁装）；网络失败诊断分类（policy/fake-ip/unresolved/network——Clash 假 IP
  单独提示）。

### 3.3 opencode（三源统一抽象 + 兼容发现）

- 发现：外部兼容 `~/.claude/skills/` + `~/.agents/skills/`（全局 + 项目上溯 worktree
  每层）；自有 `{skill,skills}/**/SKILL.md`；config 附加 `skills.paths` + **`skills.urls`
  远程索引**（`skill/index.ts:185-227`）。
- **skill 工具输出附目录文件采样**：正文 + base directory + **同目录文件清单（除
  SKILL.md 外排序取前 10）**——模型能自己引用随包 scripts（`core/src/tool/skill.ts:35-52`）。
- 内置"自救"技能 customize-opencode，用户同名可覆盖（:277-283）；技能自动升格 slash
  命令带来源 badge；permission "skill" 资源级 deny 从系统提示直接隐藏。
- 管理 UI 只有 TUI 浏览对话框（无创建/编辑/启停）。

### 3.4 cc-switch（SSOT + scan_unmanaged，Tauri 同壳同构）

- **SSOT + 投影**：技能统一存 `~/.cc-switch/skills/`，以 symlink（**auto：symlink 失败
  自动回退 copy**——Windows 无符号链接权限的务实降级）或 copy 投影到各客户端目录
  （`services/skill.rs:2445-2516`）。
- **scan_unmanaged**（:2026-2444）：在各 app 目录扫非自家管理的技能，found_in 多端
  命中去重，导入时显式勾选——与"导入扫描外部技能源"完全同构。
- 双通道发现：自配 GitHub 仓库源（内置默认 4 个：anthropics/skills 等）+ skills.sh
  市场 API 分页搜索；ZIP 本地安装带**解压安全预算**（条目数 ≤30000/总量 ≤512MiB/
  symlink 目标 ≤4KiB）。
- 卸载即备份（滚动保留 20 份）+ content_hash（SHA-256）更新检测。
- 安全：GitHub 坐标统一校验防 URL 注入；SSOT/目标目录别名检测防 symlink 互删。

### 3.5 快扫三仓增量（kimi-code / qwen-code / codex）

- kimi-code：**平面单文件技能**（skills 根下直接 .md，name/description 回退文件名/
  首行）+ `${KIMI_SKILL_DIR}` 资源定位符 + 技能 slash 命令"命名空间前缀/无冲突省略"
  降级匹配；来源根含 `~/.agents/skills`（跨工具共享生态位）。
- qwen-code：**pending-skills 暂存目录**（自动生成的技能先隔离待用户确认，发现器
  天然看不到）；TOML/MD 双格式命令 + 自动迁移；工具描述下沉为 bundled skill。
- codex：custom prompts 已被 skills 吸收（`$SkillName` sigil 提及触发）；frontmatter
  **宽容 YAML 修复**（`repair_frontmatter_scalar_fields`——第三方脏技能 fail-open）；
  `skills.list/read` 分页工具（渐进披露）；技能不跨 turn 保留语义。

## 4. 改造方案（A~F）

> 顺序即依赖序：A（导入 op）是主体；B/C/D 是同一次 UI 重做里的增量；
> E/F 为增强与记档。全部零新增 npm 依赖。

### A. 外部技能源扫描导入（用户点 1）

- 新 host op `skill-import-scan`（新文件 `src/host/skill-import-op.ts`——行数纪律
  拆分位）：
  - 扫描源表（每源 `{label, dir}`；homeDir 从网关注入——测试注入临时目录）：
    - Claude Code：`~/.claude/skills`（zcode/pi-desktop/opencode 三仓一致首源）
    - Codex CLI：`~/.codex/skills`（zcode 表）
    - 通用 agents：`~/.agents/skills`（kimi/qwen/codex/opencode 四仓的跨工具
      共享生态位——存量大）
    - OpenCode：`~/.config/opencode/skills`；Qwen：`~/.qwen/skills`；
      Trae：`~/.trae/skills`；Kiro：`~/.kiro/skills`；Roo：`~/.roo/skills`；
      Windsurf：`~/.codeium/windsurf/skills`（zcode 表补齐）
    - 工作区：`<workspaceRoot>/.claude/skills` + `<workspaceRoot>/.agents/skills`
      （项目级生态位）
  - 候选 = 源目录下**一层**扫描：子目录含 SKILL.md → 目录技能（整目录候选）；
    直接子 `.md` 文件 → 单文件技能（kimi 平面形态——导入时转成
    `<name>/SKILL.md` 目录形状落盘）。frontmatter 解析复用内核
    `parseSkillFrontmatter`（name/description/tools），body 为空跳过；
    候选带 warnings（missing frontmatter/name——pi-desktop 形态）+ bytes。
  - 产出 `{sources: [{label, dir, exists, count?, error?}], candidates: [{name,
    description?, bytes, sourceLabel, sourcePath, kind: "dir"|"file", warning?}]}`
    ——每源一行报告不静默；跨源同名先到先得（表序即优先级，与 MCP 导入同构）。
  - **导入执行**（同 op 或 `skill-import-apply`）：整目录复制（`cp recursive`，
    errorOnExist 语义）进 `<workspaceRoot>/.zcode/skills/<name>/`；**重名/目标
    已存在 → skip**（zcode sameNameExists 语义——绝不覆盖）；导入后重新扫描
    （pi-desktop 自动重扫让已导入行消失）。
  - **symlink/junction 模式不取**：我方技能根就是消费根（无多端投影需求），
    copy 已满足"快捷导入"；symlink 的跟随来源更新价值在我方单根形态下是
    意外写入面（外部工具改技能直接改到我的工作区）——记档不取（cc-switch
    需要它是因为 SSOT 多端投影，我方无此场景）。
- UI（agents.js 技能分节头部加「导入技能」按钮 + 模态）：复用 MCP 导入模态形态
  （全选/计数/刷新/来源分组/勾选行），候选行 = 勾选 + 名称 + 描述单行 +
  bytes + 来源徽章；导入后清单自动刷新。
- 验收：走查预置假 `.claude/skills/<n>/SKILL.md` → 扫出 → 导入 → 清单出现 →
  落盘核验目录形状；重名 skip。

### B. 行级管理补全（删除 + 详情）

- **删除按钮**（行级，确认弹窗）：删除 = 删技能目录（递归）。**安全护栏**
  （zcode 同构）：路径 resolve 后必须位于受控技能根（workspace 主目录或
  skills.roots 之一）内且非根本身——防配置的根指向用户主目录之类误删；
  附加根技能也可删（只读的只是编辑器写回，删除是管理面）。
- **Reveal**（pi-desktop 先例）：行菜单/按钮"打开所在文件夹"——Tauri
  `shell open` 目录；低成本的定位辅助。
- 验收：删除 workspace 技能 → 目录消失；护栏：mock 根=home 时删除被拒。

### C. 新建种子模板（pi-desktop 先例）

- 新建技能时 name 输入后 body 一次性 seed（`nameTouched` 门控不覆盖已写内容）：
  三段骨架 `## 何时使用` / `## 步骤` / `## 注意`（中文版——技能正文是我方
  中文优先约定）。
- 验收：新建 → 输名称 → 正文自动出现骨架；手改过正文不再覆盖。

### D. 编辑器增强

- **字节计数器**（pi-desktop 形态）：正文右下 `n / 128KB`，>80% 黄、超限红
  （保存按钮同步禁用）。
- **外部来源技能保存语义澄清**：编辑来源 ≠ workspace 主目录的技能时，保存前
  confirm 提示"将保存为工作区主目录的同名副本（原文件不动）"——现状是静默
  变副本，用户无感知。
- 验收：计数器变色；外部来源编辑弹确认。

### E. 附加根与清单信息面

- 来源根行加**技能计数**（该根扫出几个技能——loadSkillsFromRoots 已有 origin
  数据面）。
- 诊断行增强：诊断码 + path 已有；补琥珀色汇总（"X 个诊断"折叠——zcode 形态，
  量小则保持行式）。
- 验收：走查截图核对。

### F. 明确不做（记档）

- **技能市场/远程 URL 源**（cc-switch 双通道/opencode skills.urls/pi-desktop 市场）：
  单机单用户无分发场景，记档；导入扫描已覆盖"把外面的技能拿进来"的主诉求。
- **SSOT + 多端投影**（cc-switch）：我方单消费根，无投影需求。
- **平面单文件技能的消费形态**（kimi）：我方内核目录纪律是"有 SKILL.md 的目录
  即技能"——改成平铺双形状要动装配面；导入时已把单文件转目录形状，消费面
  不动（记档）。
- **when_to_use / license / metadata 字段**（zcode SAFE_FRONTMATTER_KEYS）：消费面
  （系统提示行）暂不消费；frontmatter 未知 key 我方解析器本就忽略——兼容不报错。
- **宽容 YAML 修复**（codex）：我方行解析对常见脏数据（description 含未加引号
  冒号/中文）已可用（`key: value` 单行正则不挑值内容）；块标量等 YAML 高级
  语法不支持，记档。
- **pending-skills 暂存区**（qwen）：我方无自动生成技能的面，记档。
- **Move 作用域转移**（pi-desktop）：我方多根是"主可写 + 附加只读"模型，无
  global/project 双写位，记档。
- **更新检测/卸载备份**（cc-switch content_hash）：copy 导入后即为我方资产，
  记档。
