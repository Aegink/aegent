## 0. 结论一句话

参考仓共同把"给 AI 的规矩"做成**五个域**：①规矩文件层级（managed→user→project→local
→rules 目录，拼接非覆盖）②权限规则（allow/ask/deny 三列+语法编辑器+审批反写）③记忆域
（人写规矩与 AI 自学笔记分离，索引+主题文件两级）④生效透明度（token 占用/加载清单/
"是否真的生效"可视化）⑤脚手架（/init 扫描生成+已有文件改进建议）。我方现状是**引擎远
强于 UI**：policy/ 域 40+ 文件的规则链（判官/审计/危险命令/样例承诺校验/linter/三层规则）
只露出"三个 textarea 编辑卡"——"一个页面就一个功能"的根源在此。改造主体：指令中心从
"三卡编辑器"升为"规矩管理中心"（层级文件树+规则表三列管理+规则测试器+生效清单+记忆
域入口+审批反写闭环）。

### 2.3 差距小结

引擎有：三层规则、参数 matcher、样例承诺、判官、审批链、linter 点名、项目信任、审计。
UI 只有：三 textarea + 一行 lint + 固定模板。**规则表没有结构化管理（三列分组/来源标注/
增删行）、没有规则测试器（输入一条命令预测放行/询问/拒绝——引擎 evaluate 原语现成）、
没有生效清单（本次会话实际装载了哪些规则/哪些文件）、没有记忆域、项目层规则与 AGENTS.md
的层级关系不可见、审批卡的"永久允许"没有反写规则文件的闭环。**

## 3. 参考仓调研

### 3.1 Claude Code（官方文档全域深读——指令域最全先例）

**A. 规矩文件层级**（【官方】code.claude.com/docs/en/memory）

- 四层：managed（`/etc/claude-code/CLAUDE.md` 等）→ user（`~/.claude/CLAUDE.md`）→
  project（`./CLAUDE.md` 或 `./.claude/CLAUDE.md`）→ local（`./CLAUDE.local.md`，
  gitignore）。**全部拼接进上下文而非覆盖**（"All discovered files are concatenated
  rather than overriding each other"）；`~/.claude/rules/` 先于项目规则。
- **`.claude/rules/` 模块化规则目录**（v2.0.64 引入）：递归发现 `.md` 可分子目录；
  frontmatter `paths`（glob）做**路径限定懒加载**——仅当 Claude 读取匹配文件时注入；
  整规则共享 1000 模式/4 MiB 预算。
- 子目录嵌套懒加载：启动只装 cwd 及祖先；子目录文件在 Read 到该目录文件时才注入。
- `@import` 语法：`@path/to/file`，递归深度 4 跳，代码块内跳过，越界导入首次弹批准。
- `claudeMdExcludes` 排除面；`/context` 里 Memory Files 段逐文件列 token 占用。

**B. 记忆域**（【官方】memory 页 + CHANGELOG）

- `/memory` 命令：列出 user/project 作用域内存文件位置（**含尚不存在的条目**引导创建）、
  切 auto memory 开关、打开文件夹、编辑器打开。
- **auto memory**（~v2.1.32）：`~/.claude/projects/<project>/memory/`；MEMORY.md 索引
  （一行一条，加载上限 200 行/25KB）+ 主题文件按需读；四类 frontmatter type
  （user/feedback/project/reference）；自动跳过可从代码库推导与 CLAUDE.md 已有内容。
- `#` 快捷记忆已移除（v2.0.70），官方路径改为对话说 "remember that…"。
- 官方坦承 CLAUDE.md 是"系统提示之后注入的用户消息"**非强制**——需要强制时用 hooks。

**C. /init 脚手架**：扫描目录结构/配置文件/源码生成涵盖构建命令/测试命令/项目结构/
架构约定的 CLAUDE.md；**已存在时建议改进而非覆盖**。

**D. permissions 权限域**（【官方】permissions 页——本批重点）

- allow/ask/deny 三列表；规则 `Tool` 或 `Tool(specifier)`。语法全集：Bash 通配
  （`Bash(npm run *)`、`:*` 后缀、复合命令逐段匹配、安全前缀剥离）；Read/Edit
  gitignore 风格路径（`//` 根/`~/` 家/`/` 相对来源/裸名任意深度、`!` 否定、Read deny
  连坐 Edit/Write）；WebFetch 域名（`domain:*.example.com`、`domain:*`）；MCP 三粒度
  （server/单工具/`mcp__*`，**allow 不接受未锚定通配——跳过并警告**）；子代理粒度
  （`Agent(Explore)` deny 即禁用）；参数匹配仅 deny/ask（`Agent(model:opus)`，主内容
  字段不可匹配）。
- **求值顺序 deny → ask → allow 首个匹配胜**；"allow 不能从 deny 里豁免"；托管层不可
  覆盖。裸工具 deny = 从上下文移除整个工具。
- settings 层级：Managed → CLI → local → project → user；列表键跨层合并非覆盖；
  allow 需先 trust 文件夹，deny/ask 即时生效；permissions 改文件**热重载**。
- 询问 UI 三态：仅本次/本会话/永久；"don't ask again" 反写**仓库根
  `.claude/settings.local.json`**（Bash 按前缀推导 `Bash(ls *)`，复合命令逐子命令最多
  5 条）；批准/拒绝可附备注；堆叠请求显示 "2 of 5" 计数。
- `/permissions` 对话框：列出全部规则**及来源文件**、按 scope 增删、改动即时生效。
- defaultMode 六档（default/acceptEdits/plan/auto/dontAsk/bypassPermissions）；auto 与
  bypass 不允许从 project/local 生效。

**E. 生效透明度**：`/context` 彩色网格（System Prompt/System Tools/MCP/Memory Files/
Skills/Messages/Free Space 分段，10x10 或 20x10）+ 逐文件 token 占用 + 优化建议。

**F. GUI 借鉴清单**（调研代理产出，10 条）：层级树呈现规矩文件（每节点标注作用域与
token 占用）/拼接非覆盖心智模型明示注入顺序/文件列表含不存在条目引导创建/记忆两级
展示（索引+主题文件+四类标签）/token 占用徽标+"最后加载时间"/权限三列分组+来源标注+
即时增删/规则语法编辑器内置模板+永匹配警告/询问弹窗三态+永久项回链/deny 恒胜可视化
（锁标）/保存后明示"下个会话或 /compact 生效"。

### 3.2 opencode（GitHub 源码深读——permission 引擎与 ask UI 先例）

**A. AGENTS.md 发现与加载**（【官方】packages/opencode/src/session/instruction.ts）

- 全局：`~/.config/opencode/AGENTS.md`（存在则遮蔽 `~/.claude/CLAUDE.md`）。
- 项目：AGENTS/CLAUDE/CONTEXT 三名兼容，findUp 沿祖先**全部注入**但三文件名取第一个
  有命中者；cwd 之下子目录的 AGENTS.md 靠**读到该目录文件时惰性注入**（每条 assistant
  消息去重一次），包裹文案 `Instructions from: <path>`。
- 自定义 `instructions` 数组：glob/`~/`/绝对路径/`http(s)://` 远程 URL（5s 超时）。
- 系统提示组装：`[agent.prompt 或 provider 基础, ...instructions, mcp_instructions,
  skills]`；自定义 agent 的 prompt **替换** provider 基础提示词，AGENTS.md 照常追加。

**B. /init 脚手架**（【官方】command/template/initialize.txt）：目标"紧凑的指令文件，
每行自问 Would an agent likely miss this without help?"；调查来源含**已有指令文件
（AGENTS.md/.cursor/rules/.cursorrules/copilot-instructions）**；"Prefer executable
sources of truth over prose"；已有文件**原地改进而非盲改**；`$ARGUMENTS` 承接聚焦参数。

**C. permission 引擎**（【官方】permission/index.ts + core/util/wildcard.ts）

- 键：`read/edit/bash/task/skill/webfetch/external_directory/doom_loop` + 通配 `"*"`；
  值 allow/ask/deny；agent 粒度覆写（`cfg.agent[name].permission` 叠加、后入者胜）。
- 通配算法（11 行）：`*`→`.*`、`?`→`.`、" *"尾特例→`( .*)?`（裸命令也匹配）、win32
  大小写不敏感；**findLast 语义——最后一条命中的规则生效**（`*` 放最前、特例放后）；
  无命中默认 ask。
- bash pattern 来源：tree-sitter 解析 + **命令前缀 arity 表**（`git:2`/`npm run:3`/
  `docker compose:3`）截取人类可读前缀 → `git push *`——**免写通配符**。
- doom_loop：最近 3 次同工具同输入 → ask。

**D. ask UI 三态**（【官方】tui permission.tsx）：Allow once / Allow always / Reject
（Esc=Reject）；edit 内嵌 diff、bash 显示 `$ command`、webfetch 显示 URL——**按权限
类型定制卡片**；"always"二次确认页列出将放行的 patterns；Reject 可附一句话反馈回传
模型（CorrectedError）；**always 是内存态不回写配置**（"until restart"——配置唯一真源
是文件，GUI 只做会话内授权）；desktop 按 session/目录记忆 auto-accept。

**E. 规则编辑 UI：没有**——TUI/desktop 均无 AGENTS.md/permission 编辑器（现实编辑
路径=外部编辑器+/init 生成），UI 只做门控与消费。**反衬：图形化规矩管理是我方 GUI 的
差异化机会。**

**F. 子代理权限**：子会话 ruleset = 父会话 deny + external_directory（"父代理的限制
只管父代理"）；AGENTS.md 对 subagent 同样生效【推断·代码路径】。

**G. GUI 借鉴清单**（调研代理产出，8 条）：ask 卡片按类型定制正文/三按钮语义固定+
always 二次确认/免写通配符（系统推导 pattern）/拒绝即纠偏（附反馈回传）/deny 即隐藏
工具/一键 auto 模式+粒度化记忆/UI 不回写配置/规则文件靠高信号模板生成。

### 3.4 pi / PI-Desktop（GitHub 源码——加载链可解释性+权限模型先例）

## 4. 参考仓共同模式（六路归纳）

1. **层级拼接而非单文件**：所有仓都是多作用域（全局→项目→子目录/私有）文件**拼接**
   进上下文，UI 责任=把"实际加载链+优先级+各层成本"讲清楚（Claude /context、gemini
   `<loaded_context>`、pi 分节、Cursor 优先级文案）。
2. **规则列表页=单一事实源**：规矩的可视形态是"文件树+规则行列表"，每行带来源层、
   状态徽标、单条开关（Cursor Rules 页/Cline Rules 面板/Claude /permissions 三家同构）。
3. **权限规则三列（allow/ask/deny）+ 语法模板 + 永不匹配警告**：Claude 最全（三列表+
   工具/路径/域名/MCP/子代理五维语法）；opencode 的免写通配（命令前缀自动推导）与
   gemini 的强制确认反向通道（优先级高于白名单）是两个互补先例。
4. **审批卡固定三态+反写闭环**：once/always(session)/deny 是各仓通配；"永久"档必须
   有 diff 预览反写（Claude 写 settings.local.json/gemini 收件箱原子应用/opencode 明示
   until restart 不回写——两派都有，反写派更适合我方 rules.txt 权威文件模式）。
5. **生成与沉淀双入口**：/init 扫描生成（Claude/opencode/qwen）+ 对话一键存规矩
   （Cline /newrule/Cursor /Generate Cursor Rules）；生成侧共识=**已有文件改进而非
   覆盖**+高信号写作准则（"每行自问 agent 不看会不会犯错"）。
6. **记忆域独立于规矩域**：人写规矩（AGENTS.md）与 AI 自学笔记（auto memory）分离，
   记忆走"索引+主题文件"两级、AI 提案经人工审核（gemini 收件箱范式最强）。
7. **生效语义明示**：规矩保存≠当前会话生效（Claude 明示"下个会话或 /compact"、pi
   /reload 热重载、gemini 事件驱动热更新）——每仓都选择了自己的语义并把它讲给用户。
