# 全站图标重设计方案（T-P3-161 需求 3——先出方案待裁决）

- 日期：2026-10-04
- 状态：**待用户裁决**（打勾 A 或 B 后实施）
- 参考基准：pi-desktop `apps/desktop/src/components/icons.tsx`（306 行）——**lucide-react 官方图标**（~100 枚）+ `strokeWidth={1.75}` + 16px 基线 + `--font-scale` 随字号缩放；zcode 同为 lucide（stroke 1.5、size-4=16px）。

---

## 一、现状问题（为什么难看）

1. **手绘 path 形不准**：ui/icons.js 61 枚是我方手写的 `<path d>`——不是 lucide 官方几何。同类图标与 pi/zcode 并排看，比例、圆角、端点都有偏差（用户观感"难看"的主因）。
2. **描边不一致**：我方 1.8 vs pi-desktop 1.75 vs zcode 1.5——同屏混用时粗细漂移。
3. **尺寸两档混乱**：我方 icon-sm=1em（随字号），pi 用固定 16px（chrome）/14px（行内）双档 + font-scale 缩放。
4. **缺口**：思考档、供应商、决策卡等新面临时借用近义图标（如模型 pill 用 sparkles），语义不准。

## 二、两个方案

### 方案 A：lucide 官方 path 全量替换（推荐）

- **做什么**：icons.js 的 PATHS 表全部换成 lucide 官方 path 数据（ISC 许可，登记 THIRD_PARTY.md 与 ui/vendor/README.md——只抄数据不引库，零构建纪律不破）；描边统一 1.75；尺寸两档：chrome 16px / 行内 14px（`--font-scale` 同款缩放后补）。
- **图标映射（核心面，全部对齐 pi-desktop 实际用法）**：

- **工作量**：icons.js PATHS 数据替换 61 枚 + 补 ~15 枚缺口 ≈ 1 个批次；消费面（语义名）不变——app/views 零改动。
- **风险**：低（纯视觉数据替换；lucide 几何在 16px 下已验证）。

### 方案 B：保留手绘，仅统一规格

- 描边 1.8→1.75、尺寸对齐 16/14 双档、缺口补手绘。
- 工作量最小，但"形不准"的根因不解决——与 pi/zcode 并排仍有肉眼差距。

## 三、验收（方案 A 打勾后）

1. 发送钮=白圆钮+上箭头、执行中=方块停止（与 pi 截图一致）。
2. 设置/通知/终端/插件四钮与 pi 截图第 4 图逐一对得上。
3. 全站 hover 与 16px 下无模糊、无粗细漂移。
4. THIRD_PARTY.md 登记 lucide（ISC）。
